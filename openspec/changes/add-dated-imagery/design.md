# Design

## Context

Мотивация — proposal. Подложки — данные `web/src/layers/catalog.ts` (`LayerDef`: один источник на код), стиль собирает `web/src/layers/style.ts` (один источник и слой на код, у горизонталей ещё подписи), выбор — стор `web/src/state/store.ts`, адрес и `localStorage` — `web/src/state/sync.ts`. Снизу по центру — строка `web/src/map/MapActions.tsx` с кнопкой профиля. Сеть `App` получает пропом `fetch`, browser-тесты подменяют тайлы `transformRequest` (`src/test/tiles.ts`), e2e — регулярками из шаблонов каталога (`e2e/fixtures.ts`).

Факты сверены 2026-10-12 `curl` с `Origin: https://nakarte-routing.pages.dev` у Казбеги (тайл z12 `2554/1509`, точка `44.6, 42.7`) и по первоисточникам:
- GIBS ([WMTSCapabilities](https://gibs.earthdata.nasa.gov/wmts/epsg3857/best/1.0.0/WMTSCapabilities.xml)): слои `HLS_S30_Nadir_BRDF_Adjusted_Reflectance` (данные с 2015-11-28) и `HLS_L30_Nadir_BRDF_Adjusted_Reflectance` (с 2013-03-22), матрица `GoogleMapsCompatible_Level12`, PNG, шаблон `…/best/<слой>/default/{Time}/{TileMatrixSet}/{TileMatrix}/{TileRow}/{TileCol}.png`. Тайл — `200`, `Access-Control-Allow-Origin: *`; z13 — `400`. Дата без съёмки над тайлом — `200`, прозрачный PNG 334 байта без заголовка `layer-time-actual`. S30 за 2026-10-10 (два дня назад) уже есть.
- Даты съёмки совпадают: у S30 тайлы есть за даты сцен `sentinel-2-l2a` (10-10, 10-05), у L30 — за даты `landsat-c2-l2` (10-08, 09-30).
- Earth Search ([`/v1`](https://earth-search.aws.element84.com/v1), STAC API Element 84, заявляет `item-search#fields` и `item-search#sort`): `GET /v1/search?collections=sentinel-2-l2a,landsat-c2-l2&intersects=<Point>&datetime=<с>/..&limit=200&sortby=-properties.datetime&fields=…` — `200`, CORS `*`; за 90 дней у Казбеги 65 сцен обеих коллекций (одним ответом), у сцены `datetime`, `platform` (`sentinel-2a/b/c`, `landsat-8/9`), `eo:cloud_cover` — на весь квадрат MGRS 110 км или сцену Landsat 185 км. В один день бывают две сцены Sentinel-2 (S2A и S2B 2026-10-07).
- Подписи: GIBS просит «We acknowledge the use of imagery provided by services from NASA's Global Imagery Browse Services (GIBS), part of NASA's Earth Science Data and Information System (ESDIS)» ([Data Use Guidance](https://nasa-gibs.github.io/gibs-api-docs/)); Copernicus — «Contains modified Copernicus Sentinel data [год]» ([лицензия](https://ads.atmosphere.copernicus.eu/licences/ec-sentinel)); USGS — «… courtesy of the U.S. Geological Survey» ([data citation](https://www.usgs.gov/centers/eros/data-citation)). Задержка HLS — 2–3 дня ([HLS](https://www.earthdata.nasa.gov/data/projects/hls)).

## Goals / Non-Goals

**Goals:** подложка снимков за дату без своего бэкенда; дата в ссылке; понятная дата по умолчанию; список дат с облачностью над тем, что на экране; тесты без сети.

**Non-Goals:** облачность над самой точкой (по маске сцены), подсказка «снимка ещё нет» по прозрачному тайлу, сравнение двух дат, MODIS и VIIRS, кеш тайлов GIBS (у них `no-store`).

## Decisions

### Одна подложка `Hls`: Sentinel-2 и Landsat вместе **[агент]**

Ресёрч оставил открытым «S30 и L30: оба или только S30». Оба: за одну дату снимок есть там, где снимал хотя бы один спутник, а прозрачный тайл второго ничего не закрывает — частота выше без выбора спутника пользователем. Плата — вдвое больше запросов тайлов, пустые по 334 байта. В каталоге у `Hls` один растровый источник, у которого `tiles` — шаблоны обоих слоёв GIBS снизу вверх (L30, затем S30) с токеном `{date}`, и признак `dated`. `style.ts` для такого слоя кладёт по источнику и слою на шаблон: нижний — `Hls@0`, верхний — `Hls` (`@` не встречается ни в кодах каталога, ни в base64url своих слоёв); ошибка тайла `Hls@0` приводится к коду до `@`. Так e2e и скрипт превью видят оба шаблона из каталога без своих списков, а каталог остаётся данными. Отвергнуто: две строки каталога (лишний слой в списке), свой протокол со склейкой двух PNG (расчёт на каждый тайл), только S30 (реже снимки, а владелец назвал оба).

Название «Satellite by date», группа `Default layers`, место в порядке — сразу после `S2`, `maxzoom` 12 (матрица GIBS), тайлы 256 px. Код `Hls` и параметр `d` не заняты: коды `src/layers.js` и ключи `enableHashState` старого клиента (`git show 015be893`), фикстура старых ссылок.

### Дата — в сторе и в `d=`, не в `localStorage` **[агент]**

Стор: `imageryDate: string | null` и `setImageryDate`. `sync.ts` читает `d=` при старте и на `hashchange` (только `ГГГГ-ММ-ДД` настоящей даты) и пишет его, пока подложка — слой с `dated`, иначе стирает. В `localStorage` дата не попадает: выбор подложки `Hls` переживает перезагрузку, а дата берётся заново по умолчанию — старая через неделю уже не «последний ясный день». Подстановка — `withDate(layer, date)` в `web/src/layers/dated.ts`: `{date}` в шаблонах и `{year}` в подписи; без даты `BaseMap` слой в стиль не кладёт — тайлы за случайную дату не грузятся. Отвергнуто: дата в коде слоя (`l=Hls:2026-10-05`) — ломает разбор `l=` и сохранённый выбор; `TIME=default` GIBS — последняя дата по миру, над районом почти всегда пустая.

### Даты и выбор по умолчанию — Earth Search над центром карты **[агент]**

Один запрос обеих коллекций (`sentinel-2-l2a`, `landsat-c2-l2`) по точке центра карты за 90 дней, `limit` 200, `sortby` по дате, `fields` — только дата, спутник и облачность. Сцены Landsat не 8 и не 9 (в коллекции весь архив Landsat) отбрасываются: L30 строится только из них. Сцены схлопываются по дню UTC: облачность дня — наименьшая из его сцен, спутники — объединение. Точка, а не bbox экрана: облачность — свойство сцены целиком, а в bbox мелкого зума попадает десяток квадратов с разными датами.

По умолчанию — самая свежая дата не моложе 3 дней (задержка HLS, `HLS_LATENCY_DAYS`) с облачностью ≤ 20 %, иначе наименее облачная из не моложе 3 дней, иначе самая свежая. 20 % — с запасом над «ясными» датами ресёрча (у Казбеги за 09-01…10-12 облачность ниже 10 % у пяти дат из 20) и ниже 10-04 (31 %), где облака уже видны на снимке; облачность квадрата 110 км над самим перевалом может быть другой, это видно на снимке. Выбранная по умолчанию дата пишется в адрес, как выбранная руками.

Запрос по умолчанию идёт, только если подложка выбрана и даты нет; список при открытии кнопки — заново, если центр карты ушёл от точки прошлого запроса дальше 0.1° (≈ 10 км), иначе прежний. Отмена — `AbortController`. Ошибка или пустой ответ — «Dates unavailable» с кнопкой «Retry»; слой без даты не рисуется. Отвергнуто: даты из GIBS `DescribeDomains` — для HLS он отдаёт весь мир и сплошной диапазон (ресёрч); подложка до ответа за «сегодня минус 3 дня» — чаще пустая карта, чем снимок.

### Кнопка даты снизу по центру **[агент]**

`ImageryDate.tsx` в строке `MapActions` слева от кнопки профиля: стеклянная капсула 36 px, как кнопка профиля, — иконка календаря, дата `ГГГГ-ММ-ДД` (тот же вид, что в адресе) и облачность, если дата из списка. Видна, только пока подложка — слой с `dated`. Нажатие открывает Popover вверх: строки дат (дата, облачность в процентах, «Sentinel-2» и/или «Landsat», у дат моложе 3 дней — «may not be ready»), отмеченная — текущая; под списком — поле `<input type="date">` «Other date» от 2013-04-11 (первые L30) до сегодня. Выбор даты закрывает список. Отвергнуто: дата в `All layers` — спрятана в списке, а меняют её чаще, чем подложку; верхняя строка — место маршрута.

### Подпись с годом даты **[агент]**

`<a href="https://nasa-gibs.github.io/gibs-api-docs/">NASA GIBS</a>`-благодарность дословно, «HLS» со ссылкой на страницу проекта, «Contains modified Copernicus Sentinel data {year}», «Landsat image courtesy of the U.S. Geological Survey». Подпись длинная, но атрибуция свёрнута кнопкой (i) после первого движения карты.

### Ошибки тайлов GIBS — без тоста **[агент]**

Найдено на скриншотах до merge: GIBS на тайл даты, над которым в этот день не снимали, отвечает вперемешку прозрачным PNG (334 или 934 байта) и `500` — восемь запросов одного тайла S30 за 2026-10-07 дали два `500`; тайл с данными (S30 за 2026-10-05) все восемь раз — `200`. Каждый `500` давал тост «Map tiles failed to load: Satellite by date» на снимке, который виден целиком. Для слоя с `dated` `App` ошибки тайлов не показывает: пустой тайл и упавший сервис выглядят одинаково — серым фоном, а дата и список на кнопке объясняют, что смотреть. Отвергнуто: тост только при `5xx` на всех тайлах подряд — свой счётчик ради случая, который пользователь видит и так.

### Без проверки в `prod-check.sh` **[агент]**

Ресёрч предлагал проверять GIBS и Earth Search в `prod-check.sh`. Скрипт проверяет только свои сервисы и не ходит к чужим сайтам (шапка скрипта), а упавший GIBS — не поломка клона: письмо «prod check failed» без возможности что-то исправить — шум. Проверка — вручную после деплоя (раздел «Проверки»). Отвергнуто: отдельный плановый workflow, как `tracestrack check`, — там ключ владельца, который он может починить; здесь чинить нечего.

## Risks / Trade-offs

- [Лимиты GIBS и Earth Search не опубликованы, SLA нет] → браузер ходит напрямую, Worker'ы клона не участвуют, денег владельца флуд не тратит; при блокировке слой пуст, остальная карта работает.
- [Облачность — на весь квадрат 110 км или сцену 185 км: «ясная» дата может быть облачной над перевалом, и наоборот] → облачность — подсказка, снимок виден сразу; список даёт выбрать другую.
- [Дата Earth Search может ещё не дойти до GIBS] → по умолчанию — не моложе 3 дней, свежие в списке помечены.
- [Вдвое больше запросов тайлов] → пустые PNG по 334 байта; растр GIBS не кешируется (`no-store`) — каждый показ из сети.
- [Earth Search ответит больше 200 сцен за 90 дней (высокие широты, перекрытия орбит)] → берётся первая страница по убыванию даты: теряются только старые даты.

Unit `catalog.test.ts` (35 слоёв, шаблоны `Hls`), `style.test.ts` (два источника `Hls@0` и `Hls`), `sync.test.ts` (`d=` читается и пишется только при `Hls`). Browser `ImageryDate.browser.test.tsx` по сценариям «Снимки по датам» (поддельный `fetch` с фикстурой, тайлы — `fixtureTiles`, внешних запросов нет). E2e «Список слоёв» — 35 флажков; `{date}` в `templateToRegExp`.

## Migration Plan

1. propose → apply → archive одним PR в `master`; все проверки `pass` на последнем коммите, merge, автодеплой.
2. После деплоя — `prod check`, вид `/` на компьютере и Pixel 7 с `l=Hls` у Казбеги; итог — в промпт следующей сессии.
3. Откат — revert и push; сохранённый выбор `Hls` после отката отбрасывается как неизвестный код (`validSelection`), `d=` остаётся в адресе незнакомым параметром.
