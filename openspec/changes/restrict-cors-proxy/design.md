# Design

## Context

Кто ходит через прокси (сверено по `src/`, security-аудит, п. 4): тайловые слои с `urlViaCorsProxy` в `layers.js` (Strava heatmap `content-a.strava.com`, swisstopo `wmts10.geo.admin.ch`, Tsvetkov `maptiles.website.yandexcloud.net`), Wikimapia через `/wikimapia/`, при печати — слои с `noCors: true` (`slazav.xyz`, `static.mapy.hiking.sk`) и все свои слои пользователя (`layers.configure`, любой хост); импорт треков (`simpleService` — любой URL, сервисы импорта), поиск mapy.cz, Bing (ключ со страницы), раскрытие коротких ссылок (`HEAD` на любой хост). Методы — только `GET` и `HEAD`.

## Goals / Non-Goals

**Goals:** прокси не пересылает тела и не ходит в наши адреса; произвольные хосты получают меньший лимит, чем тайлы слоёв.

**Non-Goals:**
- Закрыть произвольные хосты совсем: сломает импорт по ссылке и печать своих слоёв.
- Отдельный лимит heatmap Strava (выкачка от имени аккаунта владельца) — P2, если Strava начнёт жаловаться; пока сессия — секрет, а лимит 1 200.
- Маршруты прокси по ролям в адресе (`/tiles/<слой>/…`, `/import?url=`) — с новым UI (аудит системного дизайна, «Контракты»).

## Decisions

- **Роль по хосту цели, а не по адресу прокси.** Клиент не меняется: `urlViaCorsProxy` один на всё. Список `LAYER_HOSTS` — хосты из `layers.js` и `config.wikimapiaTilesBaseUrl`; `content-[a-z].strava.com` — шаблоном, как в `strava.js`. Забытый хост слоя попадает под 300 в минуту, а не под отказ: экран тайлов — десятки запросов, печать — сотни, но печать своих слоёв и так идёт под этим лимитом.
- **300 в минуту для остальных.** Импорт и поиск — единицы запросов в минуту; печать своего слоя — сотни тайлов, растеризация идёт очередью `xhrQueue`. Каждый запрос тратит ровно один счётчик, с IP — не больше 1 500 в минуту на оба.
- **Порядок проверок.** `Origin` → разбор цели → счётчик по роли цели (без цели — счётчик слоёв, как раньше) → `OPTIONS` (`204`) → метод (`405`) → нет цели (`404`) → свой адрес (`403`) → прокси. Счётчик тратится и на `404`/`405`/`403` — мусорные запросы тоже стоят вызова Worker'а.
- **Свои адреса — `403`, а не проксирование.** Worker'ы аккаунта и так недоступны (`error code: 1042`), но Pages отвечает: через прокси можно было бы гонять наши Pages Functions с IP Cloudflare.
- **`405` на `POST`.** `ALLOWED_METHODS` в preflight — `GET, HEAD, OPTIONS`, браузер сам не пошлёт `POST`.

## Risks / Trade-offs

- [Новый слой через прокси забыли внести в список] → 300 в минуту на IP вместо 1 200; комментарий у `LAYER_HOSTS` указывает, откуда список.
- [Сервис импорта когда-нибудь потребует `POST`] → вернуть метод с отдельным решением; сейчас таких нет.
