# Proposal

## Why

Security-аудит (`openspec/research/security-audit.md`, п. 4) и строка «Прокси по ролям» таблицы переделок аудита системного дизайна. `nakarte-cors-proxy` — открытый HTTP-релей: любой `http`/`https` хост, `POST` с телом, один лимит 1 200 в минуту, а `Origin` подделывается. По деньгам это ≈ $48 в месяц с IP, но подзапросы несут `CF-Worker` с нашим поддоменом: сканирование или перебор паролей через прокси приведут жалобы в Cloudflare на клон — вплоть до блокировки Worker'а. Прокси может ходить и в наши же Pages Functions (`/https/nakarte-routing.pages.dev/…` — `200`). Чистый список хостов не годится: печать своих слоёв пользователя и импорт по ссылке идут на произвольные хосты.

## What Changes

- Только `GET`, `HEAD`, `OPTIONS`; тело запроса к сервису не пересылается; остальные методы — `405`. `POST` через прокси клиент не шлёт.
- Свои адреса (`*.nakarte-routing.workers.dev`, `nakarte-routing.pages.dev` и его поддомены) — `403`.
- Прокси по ролям без правок клиента: хосты тайловых слоёв клона (`src/layers.js`, Wikimapia) — прежний счётчик 1 200 в минуту; остальные (импорт по ссылке, поиск, короткие ссылки, печать своих слоёв) — новый счётчик `OTHER_RATE_LIMITER` (`namespace_id` 1007), 300 в минуту.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `cors-proxy`: «CORS-заголовки» — методы без `POST`; новые требования «Только чтение» и «Свои адреса не проксируются».
- `worker-limits`: «Частота запросов с одного IP» — два счётчика прокси.

## Impact

- Код: `workers/cors-proxy/src/index.js`, `wrangler.toml`, тесты и `vitest.config.js`; CI — `check-cors-proxy.yml` без изменений.
- Клиент не меняется. Новый тайловый слой через прокси без записи в списке получит меньший лимит, а не отказ.
- Документация: `docs/architecture/cors-proxy.md`, `protection.md`; строка «Прокси по ролям» в аудите системного дизайна.
