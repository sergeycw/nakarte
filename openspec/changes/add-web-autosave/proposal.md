# Proposal

## Why

В новом приложении на `/next/` треки и проложенные маршруты пропадают при перезагрузке страницы: у старого клиента их держит сессия в IndexedDB ([ресёрч, п. 5 «Последствия удаления»](../../research/new-ui.md#последствия-удаления)), а в новом её нет. Ссылка «Copy link» отдаёт только геометрию, и маршрут, открытый по ней, редактируется как ломаная из сотен опорных точек. Это change 6 из [списка ресёрча](../../research/new-ui.md#changes-по-порядку): модель разметки маршрута уже есть ([add-web-route-editor](../archive/2026-10-09-add-web-route-editor/design.md), «Разметка маршрута в треке»), осталось её сохранять и передавать.

## What Changes

- Автосохранение рабочего набора (решение владельца — [record-new-ui-decisions](../archive/2026-10-08-record-new-ui-decisions/design.md), «Сессии: только автосохранение»): треки вкладки с разметкой маршрута пишутся в IndexedDB под своим именем базы на каждое изменение и восстанавливаются при загрузке. Без списка сессий, `sid=` и `BroadcastChannel`; база `sessions` старого клиента не трогается.
- Треки из адреса (`nktk=`, `nktl=` и др.) добавляются к восстановленным, а не заменяют их.
- Разметка маршрута в ссылке: строка `nktk` версии 4 получает необязательное поле разметки в отрезке. Старый клиент его пропускает и открывает геометрию, новый — восстанавливает маршрут. Трек без маршрута даёт ту же строку, что и раньше, байт в байт; контракт хранилища треков не меняется.
- Упрощение линии в ссылке и при открытии ссылки не трогает опорные точки размеченного отрезка: упрощаются только точки маршрута между ними.
- **Поведение меняется:** ссылка «Copy link» теперь несёт разметку маршрута (спека `route-editing`, «Ссылки и экспорт несут только геометрию»); экспорт в файлы — по-прежнему только геометрия.
- Тесты без сети: unit — сериализация и логика автосохранения на хранилище в памяти, browser mode — настоящий IndexedDB Chromium и «перезагрузка» повторным рендером `App`, e2e — перезагрузка страницы.
- Не входит: старый клиент (не меняется), перенос последней сессии старого клиента (change переключения), синхронизация между вкладками.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `tracks`: треки списка переживают перезагрузку страницы; треки из адреса добавляются к восстановленным.
- `route-editing`: разметка маршрута переживает перезагрузку через автосохранение нового приложения (по номерам опорных точек, а не по координатам); ссылка несёт разметку, экспорт — только геометрию.

## Impact

- Новый код: `web/src/autosave/` (запись и чтение рабочего набора, IndexedDB), разметка в `web/src/tracks/nktk.ts`, упрощение с опорными точками в `web/src/routing/line.ts`.
- Изменения: `web/src/tracks/import-result.ts`, `share.ts`, `actions.ts`, `web/src/state/store.ts`, `web/src/App.tsx`, тестовые помощники `web/src/test/`, e2e; `AGENTS.md`; ресёрч `new-ui.md` (change 6 в таблице changes — сделан) — при архиве.
- Внешние сервисы: хранилище треков (`nakarte-tracks`) — без изменения контракта: тело по-прежнему строки base64url через `/`.
- Прод: `/next/` сохраняет треки между перезагрузками; `/`, Pages Functions, Worker'ы и CI-workflow не меняются.
