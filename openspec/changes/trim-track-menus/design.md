# Design

## Context

Меню трека (`TrackExportItems.tsx`) — общее для списка треков и меню «Share track» редактора (архив `editor-name-share`): «Save as GPX», «Save as GPX with elevation», «Send to device», «Save as KML», «Copy link for track». «Save as GPX with elevation» — `saveTrackWithElevation` в `actions.ts`: запрос к API высот, ошибка API — сообщение без файла (архив `add-web-elevation-profile`). «Send to device» — окно `DeviceSendDialog` с шторкой Web Share и инструкцией для Garmin, Wahoo и COROS (архив `send-route-to-device`, состояние `deviceFile` стора, проп `shareFiles` у `App`). «Save all tracks to ZIP file» — `exportZip` в `export.ts` через `fflate`. Почему меняем — proposal, «Why».

## Goals / Non-Goals

**Goals:**
- Один пункт сохранения GPX, и в нём высоты.
- Меню трека и меню списка без лишних пунктов.

**Non-Goals:**
- KML без высот, как раньше.
- Импорт ZIP (`parsers/zip-entries.ts`, тот же `fflate`) не меняется.
- Профиль высот и API высот не меняются.

## Decisions

### «Save as GPX» — всегда с высотами, без слова о них (владелец)

Владелец 2026-10-29: «save gpx пусть будет всегда с elevation (но писать об этом не надо)». Пункт называется «Save as GPX», делает то, что раньше «Save as GPX with elevation»: высоты всех точек трека и отрезков из API высот (`exportGpxWithElevations`), индикатор загрузки в заголовке списка, пустой трек — сообщение без запросов. Пункт «Save as GPX with elevation» удалён.

### Ошибка API высот — GPX без высот и без сообщения (агент)

Раньше ошибка API давала сообщение `Failed to get elevation data: …` без файла. Теперь это единственный путь к GPX: без сети или при сбое сервиса высот файл не сохранился бы совсем. Поэтому при `ElevationError` сохраняется тот же GPX без `<ele>`, как делало окно «Send to device». Сообщения нет: владелец просил не писать о высотах, а файл всё равно получен. Ошибка другого рода (не API высот) уходит наверх, как раньше.

Сохранение — после ответа API: скачивание ссылкой `download` после `await`, как было у «Save as GPX with elevation».

### «Send to device» удалён целиком (владелец)

Владелец 2026-10-29: «send to device вообще удаляем». Удалены пункт, окно, шторка Web Share (`browserShareFiles`, `shareFiles`), инструкция для приложений и состояние `deviceFile`. Решение владельца 2026-10-12 («маршрут на устройство — файлом через «Send to device»») заменено: маршрут на устройство — файл «Save as GPX» с высотами. Ресёрч `openspec/research/device-route-sync.md` остаётся как есть: на его разделы ссылаются архивы.

### ZIP всех треков удалён (владелец)

Владелец 2026-10-29: «сохранить zip файл удаляем». Удалены пункт меню списка и `exportZip` с его тестом. `fflate` остаётся: им читаются ZIP при импорте. Тип содержимого файла экспорта — только строка: двоичный ZIP был его единственным двоичным случаем.

### Требования — заменой, а не правкой (агент)

OpenSpec не даёт убрать сценарий из изменённого требования. Сценарии «Все треки в ZIP» и «Send to device из редактора» больше не верны, поэтому «Экспорт треков» и «Поделиться треком из панели редактирования» удалены и добавлены заново под новыми именами: «Экспорт трека» и «Меню “Share track”». Сценарий «Сохранить в GPX» переходит в новое требование с тем же именем, как и его тест в `e2e/tracks.spec.ts`.

## Risks / Trade-offs

- [GPX без высот при сбое API, и пользователь об этом не знает] → решение агента выше; профиль высот трека по-прежнему показывает высоты из того же API.
- [«Save as GPX» ждёт ответа API высот] → индикатор загрузки в заголовке списка; длинные треки уходят одним запросом, как и раньше у «Save as GPX with elevation».
- [Нет ZIP всех треков] → решение владельца; все треки по-прежнему сохраняются ссылкой «Copy link for all tracks».
