# Design

## Context

Мотивация — proposal. Режим без ключа (`google.ts` ставит класс `google-street-view-keyless`, если ключ пустой) держится на `web/src/streetview/keyless.css`. Правила повторяют боевой CSS nakarte.me (архив `hide-street-view-dev-overlay`): Google ставит холсту сцены `canvas.mapsImagerySceneScene__canvas` инлайновый `filter: invert(1)`, а мы инвертируем корень сцены `div[aria-label="Street View"]` ещё раз — две инверсии гасят друг друга. В архиве причина выбора — «как у автора», других доводов нет.

Проверено 2026-10-12 на проде `nakarte-routing.pages.dev` без ключа (Maps JavaScript API 65, Playwright): в Chromium (с GPU и без WebGL), WebKit и Firefox, с локалями en и ru у холста инлайновый `invert(1)`, у корня — наш, панорама нормальная. Воспроизвести кадр пользователя удалось только подменой: со снятым инлайновым `filter` холста при нашем правиле — негатив панорамы при нормальных панелях, ровно как на кадре. Значит, у пользователя Google холст не инвертировал (почему — не видно: режим разработки Google выбирает сам, по своим причинам), а наша вторая инверсия сделала негатив.

## Goals / Non-Goals

**Goals:** нормальные цвета панорамы без ключа и тогда, когда Google инвертирует, и тогда, когда нет.

**Non-Goals:** ключ Google в проде, другие обходы режима разработки.

## Decisions

### Снять инверсию Google там, где она есть **[агент]**

`.google-street-view-keyless .gm-style [style*="invert("] { filter: none !important; }` вместо `filter: invert(1) !important` на корне сцены. Инлайновый стиль без `!important` правило с `!important` перебивает; селектор по атрибуту `style` следит за ним вживую — поставит Google инверсию позже или снимет, правило сработает или перестанет. Не завязано на класс холста: если Google перенесёт инверсию на другой элемент внутри `.gm-style` инлайновым стилем, правило её тоже снимет. Проверено подменой на проде: с инверсией Google и без неё панорама нормальная. Отвергнуто: оставить вторую инверсию и добавлять её, только если холст инвертирован, — нужен JS-наблюдатель за DOM Google ради того, что CSS делает сам.

## Risks / Trade-offs

- [Google переведёт инверсию в класс или `!important`] → правило перестанет срабатывать, панорама будет негативом Google, как без нашего CSS; признак — инлайнового `invert(` нет, а негатив есть, смотреть DOM (`AGENTS.md`, подвох про `keyless.css`).
- [Другой элемент `.gm-style` с инлайновым `invert(`, который Google инвертирует нарочно] → сейчас таких нет (проверено DOM-обходом всех элементов `.gm-style` с `filter`); в режиме без ключа правило всё равно только под классом.

## Тесты

Browser `keyless.browser.test.ts`: разметка, повторяющая Google (`.gm-style`, корень с `aria-label="Street View"`, холст), с классом режима без ключа — у холста с инлайновым `invert(1)` и у корня итоговый `filter` — `none`; холст без инверсии — тоже `none` (сценарий «Google не инвертировал панораму»); без класса — инверсия Google остаётся.

## Migration Plan

1. propose → apply → archive одним PR в `master`, merge после зелёных проверок.
2. После деплоя — панорама на проде в Chromium, WebKit и Firefox нормальная; итог — в промпт следующей сессии.
3. Откат — revert.
