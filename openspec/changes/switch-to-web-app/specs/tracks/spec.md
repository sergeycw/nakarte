## MODIFIED Requirements

### Requirement: Сохранённые сессии старого клиента не трогаются

Приложение SHALL хранить треки отдельно от сессий старого клиента на том же адресе (IndexedDB `sessions`) и SHALL NOT менять или удалять их. Если у приложения ещё нет своего сохранённого списка, оно SHALL один раз открыть треки последней по времени сессии старого клиента с разметкой маршрута и сохранить их как свой список.

#### Scenario: Сессия старого клиента

- **WHEN** на том же адресе старый клиент сохранил сессию с треками, а приложение открыто впервые
- **THEN** треки сессии в списке, проложенные отрезки размечены как в старом клиенте, сессия старого клиента остаётся на месте

#### Scenario: Свой список уже есть

- **WHEN** у приложения есть сохранённый список, а в базе старого клиента есть сессия с треками
- **THEN** приложение показывает только свой список, треков сессии в нём нет

#### Scenario: Несколько сессий старого клиента

- **WHEN** старый клиент сохранил две сессии с треками, а приложение открыто впервые
- **THEN** в списке треки только более поздней сессии
