## MODIFIED Requirements

### Requirement: Потолок ресурсов на вызов

Один вызов Worker'а SHALL прерываться платформой при превышении потолка: `nakarte-elevation` — 10 секунд CPU, `nakarte-tracks` и `nakarte-cors-proxy` — 500 мс CPU; подзапросов — 10 у `nakarte-tracks`, 50 у `nakarte-cors-proxy` и 1 100 у `nakarte-elevation` (запрос API читает не больше 512 раз, тайл — единицы).

#### Scenario: Зависший запрос

- **WHEN** вызов `nakarte-tracks` расходует больше 500 мс CPU
- **THEN** платформа прерывает его с ошибкой, а не досчитывает до 30 секунд

## ADDED Requirements

### Requirement: Бюджет чтений R2 у API высот

Запросы API высот с одного IP SHALL тратить общий бюджет чтений хранилища: запрос тратит одну единицу на каждые 64 запланированных чтения (с округлением вверх), бюджет — 32 единицы за окно 60 секунд. Запрос сверх бюджета SHALL получать `429` с теми же заголовками, что при превышении частоты. Запрос без чтений бюджет не тратит. Без IP клиента бюджет не ограничивается.

#### Scenario: Несколько длинных профилей подряд

- **WHEN** с одного IP за минуту пришли 4 запроса по 470 чтений (по 8 единиц)
- **THEN** все получают `200`

#### Scenario: Пятый длинный профиль за минуту

- **WHEN** с того же IP за ту же минуту пришёл пятый такой запрос
- **THEN** ответ `429` с `Retry-After: 60` и отражённым `Origin`
