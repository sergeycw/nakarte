# Spec Delta

## Purpose

Данные тайников geocaching.su для слоя геокешинга клона: собираются у источника по расписанию и раздаются в той же схеме, что ждёт клиент nakarte.

## ADDED Requirements

### Requirement: Файл слоя геокешинга

По адресу `geocaching_su2.json` SHALL отдаваться JSON-массив тайников, каждый — массив `[название, id, широта, долгота]`, как у файла автора на 2026-10-07.

#### Scenario: Слой геокешинга в клоне

- **WHEN** пользователь клона включает слой geocaching.su
- **THEN** тайники загружаются с адреса клона, клик по тайнику ведёт на `https://geocaching.su/cache/<id>`

#### Scenario: Схема файла

- **WHEN** собранный файл проверяется против схемы, снятой с файла автора
- **THEN** каждый элемент — массив из строки, целого и двух чисел

### Requirement: Обновление раз в сутки

Данные SHALL пересобираться не реже раза в сутки. Если сборка упала или дала пустой результат, SHALL оставаться предыдущая версия файла.

#### Scenario: Сбой источника

- **WHEN** geocaching.su недоступен во время сборки
- **THEN** файл в хранилище не меняется, сбой виден в логах

### Requirement: Бережный скрапинг

Сборщик SHALL соблюдать `robots.txt` geocaching.su, представляться своим `User-Agent` со ссылкой на проект и делать паузу между запросами.

#### Scenario: Запрещённый путь

- **WHEN** путь запрещён в `robots.txt`
- **THEN** сборщик его не запрашивает

### Requirement: Раздача с CORS и кешем

Файл SHALL отдаваться с `Access-Control-Allow-Origin: *`, сжатием и `Cache-Control` с `max-age` не меньше часа.

#### Scenario: Заголовки

- **WHEN** клиент запрашивает `geocaching_su2.json`
- **THEN** в ответе есть `Access-Control-Allow-Origin: *` и `Cache-Control` с `max-age` не меньше 3600
