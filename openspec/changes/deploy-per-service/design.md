# Design

## Context

Один job `deploy` собирал клон, публиковал Pages и деплоил три Worker'а подряд; прогон ≈ 2 минуты (Rust из кеша). Проверки сервисов — отдельные workflow `check-<сервис>.yml` с `paths:`, общий `check` (karma) деплой не ждёт по решению `add-pages-autodeploy` («Non-Goals»: karma ходит в живые сервисы импорта).

## Goals / Non-Goals

**Goals:**
- Деплой Worker'а только при изменениях в его каталоге и только после его тестов.
- Клиент не опережает сервис.
- Адреса автора в бандле видны до merge.

**Non-Goals:**
- Ждать `check` (karma) перед деплоем — причина прежняя.
- Защита ветки `master` с обязательными проверками — настройка репозитория, решает владелец.
- Preview-деплои для PR.

## Decisions

- **База сравнения — последний успешный прогон `deploy pages`, а не `github.event.before`.** С `cancel-in-progress` прогон, отменённый следующим push, не выкатил свои изменения; diff нового прогона с предыдущим push их бы потерял. `gh run list --status success` даёт коммит, который точно в проде. Упавший прогон тоже не станет базой, и следующий повторит неудавшийся деплой. Неизвестная база (первый прогон, переписанная история) — выкатывается всё.
- **Фильтр в shell-шаге, а не `dorny/paths-filter`.** Нужна своя база (выше), а не та, что умеет action; на скрипт из шести строк сторонняя зависимость не нужна.
- **Тесты сервиса — шаг того же job перед деплоем,** а не ожидание `check-<сервис>` через `workflow_run`: тот же коммит, без связки нескольких workflow. Для elevation — `cargo test` и `npm test` (wasm в `workerd`), без `fmt` и `clippy`: стиль не мешает выкатке, его ловит `check elevation` на PR.
- **Pages после Worker'ов** (`needs` + `!failure()`): контракт и клиент идут одним PR (монорепо), сервис должен успеть первым. Пропущенный Worker не блокирует Pages, упавший — блокирует.
- **Что считается изменением сборки клона:** всё, кроме `workers/{cors-proxy,tracks,elevation}/`, `docs/`, `openspec/`, `test/` (karma), `.github/` и `*.md`. `workers/tiles/` и `functions/` — часть Pages. Лишний деплой Pages дешевле пропущенного, поэтому список исключений, а не включений.
- **`check clone` на PR без файлов движка:** проверке бандла они не нужны, а сборка без образа BRouter быстрее.

## Risks / Trade-offs

- [Исключение лишнего пути из сборки клона] → правка в исключённом каталоге не выкатит Pages; список короткий и записан комментарием в workflow, ручной запуск выкатывает всё.
- [Упавший Worker блокирует сайт] → так и задумано для смены контракта; если Worker сломан независимо, ручной запуск после починки.
- [`gh run list` недоступен] → пустая база, выкатывается всё.
