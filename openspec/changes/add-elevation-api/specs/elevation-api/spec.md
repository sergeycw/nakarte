# Spec Delta

## Purpose

Сервис высот клона: по списку координат возвращает высоту над уровнем моря для каждой точки, повторяя контракт, который ждёт клиент nakarte, на данных Copernicus GLO-30.

## ADDED Requirements

### Requirement: Формат запроса и ответа

`POST /` с телом из строк `"<lat> <lng>"` через `\n` SHALL возвращать `200` и по строке на каждую точку в том же порядке: высоту в метрах с двумя знаками после точки или `NULL`. Пустое тело SHALL давать `200` с пустым ответом.

#### Scenario: Две точки

- **WHEN** клиент отправляет `41.690000 44.780000\n43.349000 42.439000`
- **THEN** ответ `200` из двух строк вида `746.00`, порядок совпадает с запросом

#### Scenario: Пустой запрос

- **WHEN** тело пустое
- **THEN** ответ `200` с пустым телом

### Requirement: Нет данных

Для точки, где у модели нет данных (море, вне покрытия), SHALL возвращаться `NULL`.

#### Scenario: Точка в море

- **WHEN** в запросе точка `43.000000 35.000000` (Чёрное море)
- **THEN** строка ответа для неё — `NULL`

### Requirement: Некорректный запрос

Строка, которая не разбирается как два числа, или координаты вне диапазона широты [-90, 90] SHALL давать `400` с телом `Invalid request`. Метод, отличный от `POST` и `OPTIONS`, SHALL давать `405`.

#### Scenario: Мусор в теле

- **WHEN** тело содержит строку `abc def`
- **THEN** ответ `400` с телом `Invalid request`

### Requirement: Лимиты запроса

Запрос больше 10 000 точек или больше 250 000 байт SHALL получать `413`.

#### Scenario: Слишком много точек

- **WHEN** в запросе 10 001 точка
- **THEN** ответ `413`

### Requirement: Интерполяция

Высота между узлами сетки SHALL вычисляться билинейной интерполяцией по четырём соседним узлам. Если хотя бы у одного соседа нет данных, SHALL возвращаться `NULL`.

#### Scenario: Точка в узле сетки

- **WHEN** точка совпадает с узлом сетки данных
- **THEN** возвращается значение этого узла

#### Scenario: Точка между узлами

- **WHEN** точка лежит посередине между двумя узлами с высотами 100 и 200 на одной строке сетки
- **THEN** возвращается `150.00`

### Requirement: Точность относительно сервиса автора

На наборе эталонных точек в горах высоты SHALL отличаться от сервиса автора не больше заданного в design допуска; отличия больше допуска SHALL объясняться разрешением данных (1″ против 3″) и быть перечислены в отчёте контрактного теста.

#### Scenario: Сверка с эталонами

- **WHEN** контрактный тест прогоняет эталонные точки из фикстуры
- **THEN** формат ответа совпадает с автором, высоты в пределах допуска

### Requirement: CORS

Ответ SHALL содержать `Access-Control-Allow-Origin` с origin запроса для разрешённых origin клона и `Access-Control-Allow-Credentials: true`; на `OPTIONS` — `204`. Чужой `Origin` SHALL получать `403`.

#### Scenario: Запрос с клона

- **WHEN** страница клона отправляет `POST` с `withCredentials`
- **THEN** ответ содержит `Access-Control-Allow-Origin` с origin клона и `Access-Control-Allow-Credentials: true`
