# Spec Delta

## Purpose

Сервис высот клона: по списку координат возвращает высоту над уровнем моря для каждой точки, повторяя контракт и данные сервиса автора (`elevation.nakarte.me`, DEM 3″ viewfinderpanoramas).

## ADDED Requirements

### Requirement: Формат запроса и ответа

`POST /` с телом из строк `"<lat> <lng>"` через `\n` SHALL возвращать `200` и по строке на каждую точку в том же порядке, без хвостового перевода строки: высоту в метрах с двумя знаками после точки (округление от нуля) или `NULL`. Хвостовой `\n` в запросе допустим. Пустое тело SHALL давать `200` с пустым ответом.

#### Scenario: Две точки

- **WHEN** клиент отправляет `43.350000 42.440000\n42.700000 44.500000`
- **THEN** ответ `200` с телом `5571.00\n4449.00`

#### Scenario: Пустой запрос

- **WHEN** тело пустое
- **THEN** ответ `200` с пустым телом

### Requirement: Нет данных

Для точки, где у модели нет данных (тайла нет, узел без значения), и для координат вне сетки (широта вне [-90, 90), долгота вне [-180, 180), `nan`) SHALL возвращаться `NULL`.

#### Scenario: Точка в открытом море

- **WHEN** в запросе точка `43.000000 35.000000` (Чёрное море)
- **THEN** строка ответа для неё — `NULL`

#### Scenario: Долгота за пределами сетки

- **WHEN** в запросе точка `43.350000 202.440000`
- **THEN** строка ответа для неё — `NULL`, остальные точки запроса обрабатываются

### Requirement: Некорректный запрос

Строка без пробела, с числом, которое не разбирается, с лишними пробелами или пустая строка не в конце тела SHALL давать `400` с телом `Invalid request`. Метод, отличный от `POST` и `OPTIONS`, SHALL давать `405`.

#### Scenario: Мусор в теле

- **WHEN** тело содержит строку `abc def`
- **THEN** ответ `400` с телом `Invalid request`

#### Scenario: Пустая строка в середине

- **WHEN** тело `43.35 42.44\n\n43.35 42.44`
- **THEN** ответ `400`

#### Scenario: GET

- **WHEN** клиент с разрешённого origin отправляет `GET /`
- **THEN** ответ `405`

### Requirement: Лимиты запроса

Запрос больше 10 000 точек или больше 250 000 байт SHALL получать `413`.

#### Scenario: Слишком много точек

- **WHEN** в запросе 10 001 точка
- **THEN** ответ `413`

### Requirement: Интерполяция

Высота между узлами сетки SHALL вычисляться билинейной интерполяцией по четырём соседним узлам. Если хотя бы у одного соседа нет данных, SHALL возвращаться `NULL`.

#### Scenario: Точка в узле сетки

- **WHEN** точка совпадает с узлом сетки данных
- **THEN** возвращается значение этого узла

#### Scenario: Точка между узлами

- **WHEN** точка лежит посередине между двумя узлами с высотами 100 и 200 на одной строке сетки
- **THEN** возвращается `150.00`

### Requirement: Совпадение с сервисом автора

На наборе эталонных точек высоты SHALL отличаться от ответов `elevation.nakarte.me` не больше допуска из design; отличия больше допуска SHALL быть перечислены в отчёте контрактного теста.

#### Scenario: Сверка с эталонами

- **WHEN** контрактный тест прогоняет эталонные точки из фикстуры
- **THEN** формат ответа совпадает с автором, высоты в пределах допуска

### Requirement: CORS

Ответ SHALL содержать `Access-Control-Allow-Origin` с origin запроса для разрешённых origin клона и `Access-Control-Allow-Credentials: true`; на `OPTIONS` — `204`. Запрос без `Origin` или с чужим `Origin` SHALL получать `403`.

#### Scenario: Запрос с клона

- **WHEN** страница клона отправляет `POST` с `withCredentials`
- **THEN** ответ содержит `Access-Control-Allow-Origin` с origin клона и `Access-Control-Allow-Credentials: true`

#### Scenario: Чужой origin

- **WHEN** запрос пришёл с `Origin: https://example.com`
- **THEN** ответ `403`
