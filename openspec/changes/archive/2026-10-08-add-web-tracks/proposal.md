# Proposal

## Why

Новое приложение на `/next/` умеет только карту и слои ([add-web-map-layers](../2026-10-08-add-web-map-layers/design.md)), а главное в nakarte — треки: открыть GPX или KML, посмотреть, поделиться ссылкой. Это change 4 из [списка ресёрча](../../../research/new-ui.md#changes-по-порядку): на треки опираются редактор маршрута (change 5), автосохранение (change 6) и профиль высот (change 7), а старые ссылки клона (`nktl=`, `nktk=` всех версий) новое приложение обязано открывать ([ресёрч, п. 6](../../../research/new-ui.md#6-контракты-которые-новый-ui-держит)).

## What Changes

- Парсеры файлов треков как чистые модули TypeScript: GPX, KML, KMZ, GeoJSON, Ozi (`plt`, `rte`, `wpt`), ZIP с любыми из них; экспорт трека в GPX и KML, всех треков — в ZIP из GPX. Справочник — `parsers/` и `geo_file_exporters.js` старого клиента.
- Чтение треков из адреса: `nktk=` версий 1–4, `nktl=` (хранилище треков клона), `nktu=` (ссылки на внешние треки), `nktp=` (точка), `nktj=` (JSON); после загрузки параметр уходит из адреса, как в старом клиенте.
- Импорт по ссылке через CORS-прокси клона: линейка Яндекс Карт, треки OSM, Sports Tracker, Tracedetrail, ссылки nakarte, любой файл трека по URL. Импорт Strava, Garmin Connect и Wikiloc не переносится (решение владельца).
- Список треков на shadcn поверх карты: новый трек, видимость, цвет, длина, переименовать, дублировать, развернуть, удалить, удалить все и скрытые, новый трек из видимых; треки и их точки с подписями рисуются на карте над слоями.
- «Copy link» для трека, всех и видимых треков: ссылка `nktl=` отдаётся только после ответа хранилища треков, а не до, как в старом клиенте ([аудит, п. 2](../../../research/system-design-audit.md#2-контракты)).
- Тесты без сети: парсеры и ссылки — на фикстурах, хранилище и прокси в browser mode и e2e подменяются.
- Старый клиент не меняется.

## Capabilities

### New Capabilities

- `tracks`: треки нового приложения — список и действия с ним, отрисовка на карте, треки из старых ссылок, ссылка на треки через хранилище.
- `track-files`: импорт треков из файлов и по ссылкам, экспорт в файлы.

### Modified Capabilities

- `web-client`: сценарий «Вид пишется в адрес» опирался на `nktl=`, который теперь разбирается и уходит из адреса.

## Impact

- Новый код: `web/src/tracks/` (модель, парсеры, экспорт, ссылки, импорт по ссылкам, список треков), стиль треков на карте в `web/src/layers/style.ts` или рядом.
- Изменения: `web/src/App.tsx`, `web/src/map/BaseMap.tsx`, стор и связь с адресом (`web/src/state/`), `web/e2e/fixtures.ts` (хранилище и прокси), `web/vitest.config.ts`, `web/package.json` (зависимости ZIP, protobuf, md5), компоненты shadcn, `AGENTS.md`.
- Внешние сервисы: хранилище треков (`config.tracksStorageServer`) — `POST`/`GET /track/{key}` без изменений контракта; прокси (`config.corsProxyUrl`) — импорт по ссылкам, роли прокси не расширяются. `ALLOWED_ORIGINS` обоих Worker'ов не включает порты `web/` (8769, 4173): локально — заглушки, живьём — на проде.
- Прод: `/next/` получает треки; `/`, Pages Functions, Worker'ы и CI-workflow не меняются.
