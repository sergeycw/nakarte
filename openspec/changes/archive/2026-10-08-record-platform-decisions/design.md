# Design

## Context

Решения приняты 2026-10-07 в ресёрче «Свои бэкенды вместо `*.nakarte.me`» (`openspec/research/own-backends.md`, коммиты `4cde7dc` и `0cea712`), до changes `add-track-storage`, `add-elevation-api` и `add-elevation-tiles`. Ресёрч удалён в `554a1fa`; исходный текст — `git show 554a1fa^:openspec/research/own-backends.md`, разделы «Решения владельца», «Хостинг», «Сервис высот» («Архитектура», «Ограничения Workers (Paid)») и «Структура репозитория». Ниже — причины в том виде, в каком они записаны там, без досочинённого, и оценка на 2026-10-08 из аудита системного дизайна.

## Decisions

### Хостинг клона и своих бэкендов на Cloudflare: Pages, Workers Paid, R2

Решение владельца. Аргументы ресёрча:

- Всё на Cloudflare: Workers Paid $5 + R2 за DEM 3″ + мелочь ≈ $5–6 в месяц, egress бесплатный.
- Hetzner рассмотрен (CAX11 + Object Storage ≈ €12.5 + VAT): дешевле не выходит, добавляет администрирование и защиту от DDoS; 2026-10-07 все CX/CAX на странице Hetzner были помечены «currently unavailable».
- Paid, а не Free: на Free потолок CPU 10 мс на вызов, сервису высот этого мало.
- Привязка к платформе ограничена: ядро высот переносимо, при упоре в лимиты API переезжает на VPS через адаптер `axum`.

Для тайлов BRouter тот же выбор отдельно обоснован в `2026-10-07-sync-world-tiles/design.md` («R2, а не свой сервер»).

Оценка 2026-10-08: подтверждается. Клон стоит ≈ $5.25 в месяц, переменная часть почти нулевая до сотен тысяч маршрутов; переезд — около недели работы (аудит, «Стоимость» и «Переносимость с Cloudflare»).

### Сервис высот на Rust

Решение владельца; отдельного «почему именно Rust» ресёрч не записал. Записаны требования, которые решение закрывает:

- Ядро без ввода-вывода (разбор запроса, поиск куска, интерполяция, ответ) и два адаптера: `workers-rs` + R2 — основной, `axum` + диск — запасной для VPS.
- Перепаковка DEM офлайн-утилитой на чистом Rust, без GDAL.
- Ограничения Workers: 128 МБ памяти на изолят вместе с wasm, поэтому только мелкие перепакованные куски, а не исходные растры; в wasm32 нет потоков и tokio.

Риск «зрелость `workers-rs` и память wasm» закрыт адаптером `server` (`2026-10-07-add-elevation-api/design.md`, «Risks / Trade-offs»).

Оценка 2026-10-08: оправдано — медиана CPU вызова 2 мс, запасной путь на VPS уже есть. Цена — отдельный тулчейн (`worker-build`, `rust-toolchain.toml`, Node 22 для тестов) и второй язык в репозитории.

### Монорепо: сервисы в `workers/<сервис>/`

Причина из ресёрча: все сервисы живут в этом репозитории, каждый деплоится и откатывается отдельно; так контракт сервиса и правка клиента идут одним PR, а спеки лежат рядом с кодом. Каталог `workers/` с апстримом не конфликтует. Сервис высот можно вынести в отдельный репозиторий, если он станет самостоятельным продуктом: воркспейс переносится целиком. У каждого сервиса свой `wrangler.toml` и свой workflow `check-<сервис>.yml` с фильтром `paths:`.

Оценка 2026-10-08: оправдано, но «одним PR» без порядка деплоя даёт окно, когда клиент новее сервиса: Pages выкатываются раньше Worker'ов (аудит, «Шаблон сервиса: тесты, CI, деплой»).

## Risks / Trade-offs

- [Дата архива не совпадает с датой решения] → дата и коммиты решения указаны в «Context».
- [Причина Rust записана не полностью] → записано только то, что есть в источнике; если у владельца была другая причина, её добавляет новый change.
