# Design

## Context

Зачем — [proposal](proposal.md); решения владельца — [ресёрч user-flows](../../../research/user-flows.md#раскладка-три-зоны) (решения **[владелец]** там не повторяются). Что есть сейчас: строка поиска (`search/search.ts`) разбирает `http(s)` ссылку только как вид карты (`search/links.ts`: Google, Яндекс `ll=`, OSM `#map=`, mapy, nakarte `m=`), незнакомая — `Unsupported link`. Поле `Track URL` в шапке списка треков (`TrackList.tsx`) зовёт `openUrl` (`tracks/actions.ts`) → `loadFromUrl` (`tracks/import-url.ts`): сервисы по очереди — линейка Яндекса `rl=`, `track://`, параметры треков nakarte в `#`, трек OSM, Tracedetrail, Sports Tracker и последним любой файл по `http(s)`; сервис сразу и узнаёт ссылку, и качает трек. Иконка `Open file` и перетаскивание файла на карту (`App.tsx`) уже есть.

## Goals / Non-Goals

**Goals:** одна строка для мест, координат, ссылок на карты и ссылок на треки; поле `Track URL` уходит без потери того, что оно понимало.

**Non-Goals:** новые источники треков (Strava, Garmin Connect, Wikiloc по-прежнему не поддерживаются), вставка ссылки во время правки линии (верхняя строка — редактор, backlog), новые тесты раскладки (решение владельца 2026-10-10).

## Decisions

Решения, которых нет в ресёрче и задаче change, помечены **[агент]**.

### Порядок разбора ссылки **[агент]**

Ссылка в поиске даёт список результатов, а не одно действие, поэтому «порядок разбора» — это порядок результатов, и Enter берёт первый:

1. **Трек из известного источника** — первый сервис `import-url.ts`, кроме «любого файла»: параметры треков nakarte (`nktk`, `nktl`, `nktu`, `nktp`, `nktj`) и `track://`, линейка Яндекса `rl=`, трек OSM, Tracedetrail, Sports Tracker. Порядок сервисов — прежний, поля `Track URL`.
2. **Вид карты** — прежние результаты `links.ts` (место и вид Google, вид Яндекса, OSM, mapy, nakarte). Ссылка nakarte с `nktk=` и `m=` даёт трек и `Nakarte view`, Яндекса с `rl=` и `ll=` — `Yandex ruler` и `Yandex map view`: вставил ссылку на трек — Enter открывает трек, а вид ссылки остаётся вторым пунктом. Ошибка разбора вида при найденном треке не показывается (ссылка OSM на трек — без `#map=`).
3. **Любой файл трека** — только если ссылка не трек известного источника и не ссылка на карту (`links.ts` ответил `Unsupported link`): один результат с именем файла из ссылки (`nameFromUrl`). Ссылка на карту с негодными координатами (`Invalid coordinates in Google link`) остаётся ошибкой: страница Google — не трек, а сообщение о координатах полезнее тоста «unsupported format».

Отвергнуто: трек вместо вида без выбора (ссылку nakarte на вид без трека и так видно, а с треком — вид пропал бы); вид первым (вставляют ссылку на трек ради трека — Enter открывал бы вид); «любой файл» рядом с ошибкой ссылки на карту (лишний пункт, который почти всегда кончается тостом). Чтобы «любой файл» не перекрывали ссылки на OSM, которые не вид (`openstreetmap.org/trace/{id}/data` — прямая ссылка на GPX), OSM без `map=` во фрагменте теперь не ссылка на карту, а `Unsupported link`; OSM с негодным `map=` — по-прежнему ошибка координат.

Разбор — без сети: сервисы `import-url.ts` разделены на узнавание ссылки (`matchTrackLink`: название и признак «любой файл») и загрузку, которая идёт только после выбора результата. Иначе каждая буква, набранная после `https://`, качала бы файл через прокси. Короткие ссылки Google и mapy, как и раньше, разворачиваются запросом `HEAD`.

### Результат-трек и выбор **[агент]**

Результат-трек — отдельный тип `TrackLinkResult` (`kind: 'track'`, `title`, `subtitle`, `url`) рядом с прежним `SearchResult`: у него нет точки, и метка ему не нужна; прежние поисковики и их тесты не меняются. Название — то, что получит трек, если сервис его знает заранее (`Yandex ruler`, `OSM track 3376100`, `Tracedetrail track 123`, `Sports Tracker activity`, имя файла), у ссылки nakarte — `Tracks from link`; подпись — `Open as track`, у «любого файла» — с хостом (`Open as track · example.com`): имя из пути часто ничего не говорит (`data`, `123`). Мусор после `track://` — ошибка трека (`CORRUPT`) с тостом, а не исключение: результат показывается на любую строку. Выбор зовёт прежний `openUrl` с показом трека на карте (как треки из адреса, `fitView`), очищает строку (как поле `Track URL` после загрузки) и возвращает фокус карте; метки нет. Ошибки загрузки — прежние тосты импорта (`Could not download file…`, `…unsupported format…`, причины сервисов). Отвергнуто: показывать трек без сдвига карты, как поле `Track URL`, — выбор результата поиска всегда переводит карту, и трек вне экрана выглядел бы как «ничего не произошло».

`track://` — тоже ссылка для поиска (`isLinkQuery`), хотя не `http(s)`: её понимало поле.

### Плейсхолдер и пустой список **[агент]**

Плейсхолдер — `Search or paste a track link` (набросок владельца в ресёрче — «search or paste a track link»), `title` перечисляет всё: `Search places, coordinates, map or track links (Alt+L)`. Длинный плейсхолдер на телефоне и так обрезан (раздел «Телефон» ресёрча). Подсказка пустого списка — `No tracks yet: open or drop a file, paste a link into search or draw a new one`. `aria-label` строки (`Search`) не меняется — по нему ищут тесты.

### Тесты

Новое поведение — unit и browser: `search.test.ts` (порядок результатов, «любой файл», ошибки ссылок на карты, без сети), `import-url.test.ts` (`matchTrackLink`), `Search.browser.test.tsx` (сценарии новых требований `map-search` «Ссылки на треки в поиске», «Выбор ссылки на трек» и изменённый «Неизвестная ссылка»). Тесты поля `Track URL` переносятся, сценарии не теряются: browser «Файл по ссылке через прокси клона» (`TrackList`) и e2e «Трек OSM» (`tracks.spec.ts`) — вставкой в строку поиска и Enter; browser «Хоткей в поле ввода» (`RouteEditor`) — полем `Track name` строки редактора (поле `Track URL` во время правки и так было вне экрана; сценарий `route-editing` поправлен дельтой). Ошибка загрузки из поиска — browser «Ссылка не скачалась». Плейсхолдер и `title` не проверяются: это вид (решение владельца). Тестов раскладки нет.

### Ревью диффа

Независимое ревью субагентом 2026-10-10, высоких нет. Исправлено: сценарий `route-editing` «Хоткей в поле ввода» говорил об удалённом поле (дельта); шапка ресёрча; мусор после `track://` давал необработанный reject без тоста; подпись «любого файла» без хоста; тип результата различался по наличию поля — теперь `kind: 'track'`; тест ошибки загрузки из поиска, имя теста `TrackList` — по сценарию «Файл по ссылке»; задачи. Оставлено (раздел «Risks»): поздний трек сдвигает карту, повторная загрузка той же ссылки, файлы на хостах карт и ссылки OSM, которые не вид.

## Risks / Trade-offs

- [Незнакомая ссылка теперь предлагает скачать файл, хотя раньше поиск отвечал `Unsupported link`] → так понимало поле `Track URL`; пункт подписан `Open as track`, неудача — прежний тост импорта.
- [Ссылку на трек во время правки линии не вставить: верхняя строка — редактор] → поле `Track URL` тогда тоже было недоступно (списка нет); пункт backlog про Alt+L дополнен.
- [Ссылка на карту с негодными координатами не предлагает «любой файл»: экспорт KML Google My Maps (`google.com/maps/d/kml?…`) больше не пробуется скачать] → Google и раньше отвечал прокси капчей (`links.ts`, `unsorry`); OSM без `map=` уже отдан файлу (раздел выше).
- [OSM без `map=` — не только GPX: `openstreetmap.org/node/123` теперь «любой файл» и кончается тостом «unsupported format», а не ошибкой координат] → подпись `Open as track · www.openstreetmap.org` честно говорит, что будет.
- [Трек грузится долго (прокси), пользователь тем временем выбрал место — догрузившийся трек уводит карту к себе] → так же ведут себя треки из адреса; отслеживать «карта уже двигалась» — лишнее состояние ради редкого случая.
- [Ту же ссылку можно выбрать снова, пока она грузится, — трек добавится дважды; поле `Track URL` на время загрузки выключалось] → индикатор загрузки на кнопке `Tracks` остался; дубль удаляется из меню трека.
