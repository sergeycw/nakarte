# Design

## Context

После `track-color-picker` палитра — строка шести готовых цветов, под ней строка до шести недавних своих и пикер (`web/src/tracks/ColorPicker.tsx`). Владелец 2026-10-11: вторая строка выглядит как перенос, цвета — одной строкой из шести, недавние вытесняют готовые. Попап палитры — `Popover` Base UI: при открытии он переносит фокус на первый фокусируемый элемент, и рамка `focus-visible` первой кнопки на скриншоте владельца выглядела как выбранный цвет.

## Goals / Non-Goals

**Goals:** одна строка из шести цветов при любом числе недавних; рамка фокуса не путается с выбранным цветом.

**Non-Goals:** вид пикера, формат цвета, хранение недавних (ключ и форма записи те же).

## Decisions

### Строка: недавние слева, готовые справа **[владелец]**

Шесть мест: сначала недавние, свежий первым, потом готовые по порядку `TRACK_COLORS`, лишние готовые справа не показываются. Кнопки и подписи те же (`Recent color #rrggbb`, `Color N`): номер готового цвета не зависит от места в строке. Если выбранный готовый цвет выпал из строки, он встаёт последним вместо крайнего готового: цвета по кругу дают 4–6-му треку именно выпадающие красный, розовый и жёлтый, а строка без выбранного путала бы так же, как рамка фокуса.

### До трёх недавних **[агент]**

При шести недавних готовых не осталось бы совсем, а это цвета по умолчанию и цвета ссылок старого клиента. Предел — три: в строке всегда первые три готовых (синий, оранжевый, голубой) и до трёх своих. `RECENT_COLORS_LIMIT` = 3; записи с шестью цветами читаются, лишние отбрасываются при чтении. Отвергнуто: строка с прокруткой (вариант владельца отверг) и кнопки уже (мельче цель для пальца).

### Фокус при открытии **[агент]**

Причина рамки проверена в Chromium (Playwright, прод против сборки change): после работы с клавиатурой (hex и Enter, затем Escape) повторное открытие мышью ставит фокус Base UI на `Color 1` с видимой рамкой `:focus-visible`; без клавиатуры рамки нет. Касанием Base UI 1.8.0 и раньше фокусировал сам попап (`createDefaultInitialFocus`), так что кадр владельца — с мыши.

`initialFocus` попапа — функция от способа открытия. Мышь, палец, перо — фокус на сам попап (`role="dialog"`, без рамки): рамки на кнопке цвета нет, а клавиши внутри попапа по-прежнему не доходят до редактора (`editorKey` в `MapEditor.tsx` пропускает `[role="dialog"]`; если оставить фокус на кнопке-триггере, Escape закрыл бы палитру и закончил рисование). Клавиатура — фокус на выбранный цвет в строке, если он там есть, иначе — на первую кнопку (поведение Base UI). Отвергнуто: убрать рамку `focus-visible` у кнопок — с клавиатуры её не было бы видно.

## Ревью диффа

Независимое ревью субагентом 2026-10-11, High нет. Medium, исправлено: у 4–6-го трека выбранный готовый цвет выпадал из строки при любом недавнем — выбранный встаёт последним, сценарий «Выбранный готовый цвет в строке»; предел недавних 3 не проверялся ни одним тестом (тот же сценарий со старой записью из шести); причина рамки для касания была не та — для касания Base UI и раньше фокусировал попап, рамку при открытии мышью после клавиатуры подтвердил скрипт на проде и сборке (раздел «Фокус при открытии»). Low, исправлено: устаревшие комментарии `recent-colors.ts`, запасной вариант фокуса в сценарии, ссылка на архив в `AGENTS.md`. Low, оставлено: Tab из попапа к кнопкам тестом не проверен (по DOM — первая кнопка). Проверено ревью: `initialFocus` по типам и реализации Base UI 1.8.0 (вызов после layout effect, попап с `tabIndex=-1`), `ref` через `PopoverContent` в React 19, отдельные refs у палитр списка и редактора, ключи строки, новые тесты падают на старом коде.

## Тесты

Browser `TrackList.browser.test.tsx`: «Недавние цвета» — в строке шесть кнопок, первая `Recent color #14b8a6`, `Color 6` нет; «Выбранный готовый цвет в строке» — старая запись из шести недавних даёт три, у трека с `Color 6` строка: три недавних, `Color 1`, `Color 2`, `Color 6` (предел и выпавший выбранный); «Фокус при открытии» — после нажатия на кнопку цвета `document.activeElement` — попап, после Enter на кнопке цвета с клавиатуры — кнопка выбранного цвета. Тест проверяет элемент в фокусе, а не видимую рамку; рамку проверил скрипт Playwright (раздел выше).

## Risks / Trade-offs

- [Три последних готовых цвета (красный, розовый, жёлтый) пропадают из строки, пока есть недавние] → выбранный из них остаётся в строке, остальные — через hex; если понадобятся чаще, предел — 2.
- [Свой цвет из старой записи недавних, четвёртый и дальше, теряется] → это удобство одного браузера.
