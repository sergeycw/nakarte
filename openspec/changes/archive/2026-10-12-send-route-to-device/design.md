# Design

## Context

Зачем — [proposal](proposal.md); факты о Garmin, Wahoo, COROS и Web Share со ссылками на первоисточники и решения владельца — [ресёрч device-route-sync](../../../research/device-route-sync.md) (там не повторяются). Что есть сейчас: пункты экспорта трека — общий компонент `TrackExportItems.tsx` для меню трека в списке и меню «Share track» редактора ([editor-name-share](../2026-10-10-editor-name-share/design.md)); GPX с высотами — `exportGpxWithElevations` в `tracks/export.ts` и действие `saveTrackWithElevation` в `tracks/actions.ts` (ошибка API высот — сообщение без файла); сохранение — ссылка `download` на Blob (`saveFile`). Окна поверх карты — состояние в сторе и компонент в `TrackDialogs.tsx` (`CopyFallbackDialog`, `PointNameDialog`); сеть и буфер обмена `App` принимает пропами (`fetch`, `writeClipboard`), browser-тесты подставляют свои.

## Goals / Non-Goals

**Goals:** одним пунктом меню получить GPX с высотами в приложение устройства: шторка «Поделиться», где браузер её даёт, иначе скачивание, и что делать с файлом дальше.

**Non-Goals:** прямая отправка в облака (решения владельца 2026-10-12), FIT, выбор бренда в окне, разбор `User-Agent`, проверка шторки iOS в тестах (только на телефоне владельца).

## Decisions

Решения, которых нет в ресёрче и задаче change, помечены **[агент]**.

### Окно, а не сразу шторка

`share()` требует свежего действия пользователя ([W3C Web Share](https://w3c.github.io/web-share/)), а файл с высотами собирается после ответа API высот: к его приходу активация нажатия на пункт меню уже может истечь, и шторка не откроется. Поэтому пункт «Send to device» открывает окно и сразу собирает файл, а шторку открывает отдельная кнопка «Share» в окне — её нажатие и есть свежее действие (ресёрч, «Что решить в change»). Пока файл собирается, кнопки неактивны, в окне — «Preparing GPX…».

### Одно окно на три бренда **[агент]**

Инструкция — три коротких блока Garmin Connect, Wahoo, COROS, у каждого два-три шага и ссылка на статью справки; выбора бренда нет. Отвергнуто: выбор бренда перед файлом — лишний шаг, а файл у всех один. Тексты окна — английские, как весь интерфейс; шаги повторяют справку:
- Garmin Connect: на телефоне — «Поделиться» → Garmin Connect, на сайте — Training & Planning → Courses → Import; потом «Send to Device» в Garmin Connect ([Garmin Support](https://support.garmin.com/en-US/?faq=wKuZXCaZRP4mWPX5aRz5h5)).
- Wahoo: открыть файл в Wahoo app (ELEMNT ACE, BOLT 3, ROAM 3; у старых ELEMNT, BOLT, ROAM — ELEMNT app), затем Explore → My Collection → My Routes → маршрут → Send to ELEMNT ([Wahoo Support, 2026-07-08](https://support.wahoofitness.com/hc/en-us/articles/25936827245970)).
- COROS: открыть файл в COROS app → Save, затем Explore → библиотека маршрутов (иконка справа сверху) → маршрут → Sync with Your Device → Send ([COROS Support, 2026-10-04](https://support.coros.com/hc/en-us/articles/24181489692436)).

### Файл — GPX с высотами, при ошибке API — без высот **[агент]**

Файл собирает тот же `exportGpxWithElevations`, что и «Save as GPX with elevation»; индикатор загрузки в заголовке списка не нужен — ожидание видно в окне. Если API высот не ответил (`ElevationError`), окно получает обычный GPX (`exportTrack`) и строку `Elevation data unavailable: <причина>. The file has no elevation.`. Отвергнуто: отказ без файла, как у «Save as GPX with elevation», — там пользователь выбрал файл с высотами явно, а здесь цель — маршрут на устройстве; GPX без высот приложения принимают. Пустой трек — сообщение `Track is empty, nothing to save`, окно не открывается и запросов нет. Если окно закрыли до ответа API, ответ отбрасывается: окно хранит номер запроса.

### Шторка и откат на скачивание

Кнопка «Share» есть, только если у браузера есть `navigator.share` и `navigator.canShare` (Firefox на Android файлов не отдаёт — ресёрч, «Файл в приложение: Web Share»). Нажатие сразу, без `await` до вызова, зовёт `share({ files: [File] })` с файлом окна: имя — как у «Save as GPX», тип `application/gpx+xml`. Заранее путь не выбрать: Chromium `canShare` отвечает `true` и для `.gpx`, а `share()` отклоняет его с `NotAllowedError` (ресёрч там же). Поэтому:
- успех — окно закрывается;
- `AbortError` — пользователь закрыл шторку, ничего не происходит, окно остаётся;
- любая другая ошибка (`NotAllowedError`, `TypeError` и прочие) — файл скачивается тем же путём, что «Download», окно остаётся с инструкцией. **[агент]**: не только `NotAllowedError` и `TypeError` — неизвестная ошибка не должна оставлять пользователя без файла; скачивание после отказа шторки — второй файл, а не повтор шторки.

«Download» есть всегда: на компьютере файл чаще нужен для импорта на сайте Garmin Connect.

### Шторка — проп `App` **[агент]**

`App` принимает `shareFiles?: ((files: File[]) => Promise<void>) | null`, как `writeClipboard`: по умолчанию — `navigator.share` при наличии `share` и `canShare`, иначе `null` (кнопки «Share» нет). Browser-тесты подставляют свою функцию: шторка открылась, отказ, отмена — без настоящей шторки, которой в headless Chromium нет; `renderApp` по умолчанию даёт `null`. Скачивание в unit-тестах — проп `save` действий треков, в browser-тестах — перехват `click` ссылки `download` (`vi.spyOn(HTMLAnchorElement.prototype, 'click')`; раньше скачивание проверялось только событием `download` в e2e).

### Где живёт логика

Действия без React — в `tracks/actions.ts`: `sendToDevice(track)` (проверка пустого трека, номер запроса, сборка файла, откат без высот), `shareDeviceFile()`, `downloadDeviceFile()`; состояние окна — `deviceFile` в сторе (`trackName`, `file` или `null` пока собирается, `elevationError`, номер запроса). Окно — `DeviceSendDialog` в `TrackDialogs.tsx`, рядом с `CopyFallbackDialog`; пункт — в `TrackExportItems.tsx` после «Save as GPX with elevation». Так unit-тесты проверяют файл и откат без карты, а browser-тест — окно и шторку.

### Тесты

Названия — сценарии спеки. Unit (`actions.test.ts`, describe `Send to device`): «Файл для устройства» (высоты в файле, окно ждёт ответа), «Высоты недоступны», «Пустой трек на устройство», ответ после закрытия окна отброшен, «Отправить через шторку» (`share()` вызван в том же такте, что нажатие, — без этого Safari шторку не откроет), «Браузер не отдаёт файл», `TypeError` шторки, «Шторку закрыли», «Нет Web Share». Browser (`TrackList.browser.test.tsx`, describe `Send to device`): «Файл для устройства» (ожидание, неактивные кнопки), «Отправить через шторку» (`Kazbek.gpx` типа `application/gpx+xml`, окно закрылось), «Браузер не отдаёт файл», «Шторку закрыли», «Нет Web Share», «Высоты недоступны», «Инструкция для приложений» (три ссылки, `target="_blank"`); `RouteEditor.browser.test.tsx` — «Send to device из редактора». Сеть высот — проп `fetch` у `App`.

### Ревью диффа

Независимое ревью субагентом 2026-10-12, высоких нет. Исправлено: окно без прокрутки уходило за край телефона, повёрнутого горизонтально (740×360), — `max-h` и прокрутка; тесты не ловили `await` перед `share()` — unit-тест проверяет вызов в том же такте; второе нажатие «Share» при открытой шторке скачивало файл (`InvalidStateError`) — кнопка неактивна, пока шторка открыта; начальный фокус падал на ссылку Help Garmin — фокус на главной кнопке; тесты ожидания и `target="_blank"`. Оставлено (риски ниже): неожиданная ошибка сборки закрывает окно без тоста — как у «Save as GPX with elevation»; запрос высот не отменяется закрытием окна; «Share» на десктопном Chrome всегда кончается скачиванием.

## Risks / Trade-offs

- [Есть ли Garmin Connect, Wahoo и COROS в шторке iOS для `.gpx` из Safari, не проверено (ресёрч)] → после деплоя владелец проверяет на телефоне; если их нет — «Download» и «открыть в» из «Файлов» (у COROS этот путь документирован).
- [На Chrome — Android и десктоп — «Share» всегда кончается скачиванием: `share` и `canShare` есть, `.gpx` нет в списке типов] → на Android это и есть путь (ресёрч, «Итог»); кнопка остаётся: заранее отличить браузер можно только по `User-Agent`, на Safari macOS шторка даёт AirDrop на телефон, а отказ стоит одного нажатия.
- [Закрытие окна не отменяет запрос высот: длинный трек дошлёт куски и потратит лимит Worker'а высот] → ответ отбрасывается; отмена нужна, только если на это пожалуются: тот же запрос у «Save as GPX with elevation».
- [Garmin видит 15 символов названия курса] → не правим: название задаёт пользователь, при импорте Garmin даёт его переименовать.
- [Приложения могут не принять наш GPX (`trk` с фиктивным `time` 1970 года)] → проверить на устройствах владельца; `time` оставлен ради старого импорта Garmin Connect (комментарий в `toGpx`).

## Migration Plan

1. propose → apply → archive одним PR в `master`; все проверки `pass` на последнем коммите, merge, автодеплой.
2. После деплоя — `prod check`, вид `/` и меню трека на компьютере и Pixel 7; владелец проверяет шторку iOS и импорт в свои приложения.
3. Откат — revert и push: форматы ссылок, файлов и автосохранения не меняются.
