# Design

## Context

Третий и последний change фидбека владельца 2026-10-10 (backlog, «Интерфейс после макета 4a»). Панель `All layers` — `PopoverContent` Base UI в `web/src/layers/LayerSwitcher.tsx` слева от столбца быстрых слоёв (`side="left"`, `align="start"`): ширина `w-72` (288 px), строки `min-h-7` (28 px), подсказка зума второй строкой, все подложки и оверлеи подряд, высота — `100dvh − 1.5rem`. По умолчанию в списке 8 подложек и 5 оверлеев (`isDefault` каталога); после `Configure layers` — до 32 слоёв в шести группах каталога (`GROUPS`) и свои слои.

## Goals / Non-Goals

**Goals:** панель занимает меньше карты: строки ниже, ширина по содержимому, высота не больше окна; подложки видны сразу, оверлеи и редкие группы — по нажатию.

**Non-Goals:** быстрые слои справа (превью, переключатели `Sa` и `Hs`); диалоги `Configure layers` и `Add custom layer`; каталог и порядок наложения слоёв.

## Decisions

### Подложки сразу, оверлеи — свёрнутыми секциями **[владелец]**

Подложки — одним `RadioGroup` без заголовка, как раньше: выбор подложки — самое частое действие панели. Оверлеи — секциями с кнопкой-заголовком (шеврон, название, «N on» при включённых).

### Какие группы редкие **[агент]**

Владелец назвал «оверлеи и редкие группы», не перечислив группы. Правило выводится из каталога, без списка в коде: группа **обычная**, если в ней есть слой по умолчанию (`isDefault`) — это `Default layers`, `Miscellaneous` (`Hs`) и `Routes and traces` (`Sa`); их оверлеи — в одной секции `Overlays`. Остальные — **редкие**, у каждой своя секция в порядке `GROUPS`: `Topo maps`, `Norway` и `Custom layers` (свои слои — `isDefault: false`). `OpenStreetMap alternatives` тоже редкая, но в ней только подложки, а подложки всегда в общем списке: `Overlays` первой, потом редкие (`overlaySections`); группа, которой нет в `GROUPS` (новая в каталоге), — секцией в конце, а не пропадает. Внутри секции — порядок наложения каталога, как был.

Отказались: секция на каждую группу каталога, включая обычные, — `Default layers` над оверлеями читается как «подложки», а одиночные `Miscellaneous` и `Routes and traces` добавляют заголовок на каждый оверлей по умолчанию. Список редких групп в коде — расходится с каталогом при новых слоях.

### Секция с включённым оверлеем раскрыта **[агент]**

Свёрнутым по умолчанию остаётся то, где ничего не включено (так выглядит панель на чистом заходе — решение владельца). Секция с включённым оверлеем раскрыта: видно, что включено, и выключить можно без лишнего нажатия; ссылка `l=O/Gbt` открывает панель с раскрытой `Topo maps`. Свёрнутой секции заголовок говорит «1 on». Флажок в секции закрепляет её раскрытой: правило «раскрыта, пока есть включённый» без этого сворачивало секцию под курсором при снятии последнего флажка, а фокус с флажка уходил в невидимую секцию (нашло ревью). Выбор пользователя (раскрыл, свернул или нажал флажок) держится в состоянии `LayerSwitcher`, пока страница открыта, в том числе между открытиями панели; в `localStorage` не пишется — панель открывается редко, лишняя запись в настройки слоёв не окупается.

### Свёрнутая секция задаёт ширину **[агент]**

Ширина — `w-max`: по самой длинной строке, не шире `min(20rem, 100vw − 4.5rem)` (4.5rem — столбец кнопок справа с отступом). Первая версия прятала свёрнутую секцию из разметки (Base UI `Collapsible`), и на Pixel 7 landscape раскрытие `Overlays` расширяло панель с 155 до 299 px вправо, поверх столбца кнопок: замер `getBoundingClientRect` в headless Chromium через 500 мс после нажатия — `x` прежний, правый край 903 при кнопке на 815; панель встала на место только при следующем раскрытии. Почему `autoUpdate` позиционера (у Base UI с `elementResize`) этого не поправил, не разбирали: проще убрать саму причину. Свёрнутая секция остаётся в разметке — `invisible h-0 overflow-hidden` (`visibility: hidden` убирает строки из фокуса и дерева доступности, `inert` — подстраховка), ширина панели постоянна. Своя кнопка с `aria-expanded`/`aria-controls` вместо `Collapsible`: без новой зависимости в `optimizeDeps` browser-тестов. Ширина 299 px по умолчанию — из-за «Mountains by Aleksey Tsvetkov zoom ≥ 2» в свёрнутой `Overlays`; уже, чем было (288 px плюс вторая строка подсказки), не получается, не обрезая название.

### Высота — по месту от позиционера **[агент]**

`max-h-(--available-height)`: Base UI отдаёт высоту, доступную панели у края окна, и, если от кнопки `All layers` вниз места мало, ставит её по месту: по умолчанию у поповера выравнивание сначала переворачивается (`align: 'flip'`, `start` → `end`), потом сдвигается (`internals/useAnchorPositioning.mjs` Base UI 1.8). Замеры: компьютер 1280×480 с раскрытыми секциями — панель 5–475 px, прокрутка 512 → 468; Pixel 7 landscape (окно 360–377 px по высоте) — 5–355 px, прокрутка; 1280×300 — 5–295 px; Pixel 7 портрет — панель от кнопки вниз целиком, без прокрутки. Сторона всегда `left`, переход на верх или низ (`fallbackAxisSide`) не наблюдался, настройка не нужна. `overscroll-contain` — прокрутка панели не уходит в страницу.

### Строки ниже **[агент]**

Строка 24 px (`min-h-6`, `leading-tight`) вместо 28, подсказка зума — после названия в той же строке, `whitespace-nowrap`; отступы панели `p-1.5`, промежутки 2 px; `Configure layers` и `Add custom layer` — кнопки `xs`. Строка 24 px — меньше рекомендуемой цели касания 44 px, но кликабельна вся строка шириной в панель, а прежние 28 px тоже были меньше; владелец просил ниже.

### Тесты

Новое поведение — browser-тесты (`LayerSwitcher.browser.test.tsx`), названия — сценарии спеки: «Полный список» (секция `Overlays` свёрнута, `Relief shading` не виден, после нажатия — виден, кнопки внизу), «Редкие группы свёрнуты» (`Norway` и `Topo maps` свёрнуты, раскрытие одной не трогает другую), «Секция с включённым оверлеем раскрыта» (`l=O/Hs` — `Overlays 1 on` раскрыта, снятие флажка её не сворачивает, свёрнутая пользователем остаётся свёрнутой после закрытия и открытия панели). Существующие: «Порядок оверлеев», «Включить отмывку» (browser) и «Перезагрузка без l=», «Сохранённые настройки со старыми кодами» (e2e) раскрывают нужную секцию перед кликом. Тестов вида (высота строк, ширина, прокрутка) нет — решение владельца, backlog «Тесты раскладки»; вид — скриншотами.

### Ревью диффа

Независимое ревью субагентом 2026-10-10. High: секция схлопывалась при снятии последнего включённого флажка (правило «раскрыта, пока есть включённый» считалось на каждом рендере) — флажок теперь закрепляет секцию раскрытой, сценарий и тест дополнены. Medium: в design неверно описаны выравнивание по умолчанию у позиционера Base UI (`flip`, а не `shift`) и причина наезда панели на столбец (утверждалось, что позиционер не пересчитывает размер, а `autoUpdate` с `elementResize` у него есть) — записаны как наблюдение. Low, исправлено: оверлей группы вне `GROUPS` пропадал из списка; в backlog «Полный список слоёв» ушёл из непокрытых целиком, хотя ширина и прокрутка тестами не покрыты; комментарий приписывал `inert` то, что делает `invisible`. Проверено ревью: `max-h-(--available-height)` даёт `max-height: var(--available-height)` в сборке, якорь строки `decisions.md` совпадает с заголовком, свои подложки — в `RadioGroup`, свои оверлеи — в `Custom layers`.

## Risks / Trade-offs

- [Оверлей по умолчанию (`Mt`, `Q`, `Z`) теперь в один клик дальше] → `Sa` и `Hs` — переключатели в столбце справа; секция с включённым раскрыта.
- [Ширина задаётся и свёрнутыми строками: длинное название своего слоя расширит панель] → потолок `20rem`, дальше перенос строки.
- [Состояние секций теряется при перезагрузке] → по умолчанию правило «включённое раскрыто» восстанавливает нужное.

## Migration Plan

1. propose → apply → archive одним PR в `master`; все проверки `pass` на последнем коммите, merge, автодеплой.
2. После деплоя — `prod check`, вид `/` на компьютере и телефоне; итог — в design следующего change.
3. Откат — revert и push: настройки, ссылки и автосохранение не меняются.
