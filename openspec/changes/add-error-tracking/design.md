# Design

## Context

- Точка входа приложения — `web/src/main.tsx`: `createRoot(...).render(<App />)` без своего обработчика ошибок; React 19.3, Vite 8, сборка клона — `vite build --mode clone` в корневой `build/`.
- Ключ Google уже идёт по нужной схеме: секрет `GOOGLE_MAPS_API_KEY` → `VITE_GOOGLE_MAPS_API_KEY` только шагу `web build` в `deploy-pages.yml` → `makeConfig` в `web/src/config.ts`; без секрета — пустая строка (требование «Ключ Google только шагу сборки» спеки `clone-deploy`).
- e2e идут против `vite preview` той же сборки, что выкатывается (в деплое — с секретами), и валят тест на любом запросе мимо `localhost` и заглушек (`network.external` в `web/e2e/fixtures.ts`). Сторонний скрипт в e2e уже подменяется: `FAKE_GOOGLE_MAPS`.
- Движок: `startBackends` в `web/src/engine/engine.ts` пробует бэкенды по очереди (`worker`, потом `main-thread`); ошибка каждого ловится и отбрасывается, наружу выходит только итоговый `EngineStartError`. Сбой запуска не залипает: следующий запрос маршрута запускает движок снова. Воркер классический и без импортов (`AGENTS.md`, подвохи), его ошибки уже приходят на главный поток: сообщение `start-failed` и событие `error` воркера (`backends.ts`). Отказ прокладки маршрута — `route-failed` с текстом BRouter.
- В адресе страницы — вид карты и треки (`m=`, `nktk`, `nktl`, `r=` и прочие параметры `src/state/sync.ts`), в адресах запросов — координаты (API высот, BRouter) и номера тайлов, то есть место пользователя.
- Требование «Секреты только у шагов публикации» (`clone-deploy`) держит секреты подальше от `npm ci`, тестов и сборки: там исполняется код зависимостей.

## Goals / Non-Goals

**Goals:**

- Видеть ошибки пользователей со стеком по исходникам, браузером и версией сборки, не отправляя место пользователя и его треки.
- Ноль запросов к Sentry без ошибок и без DSN: e2e, dev и форки работают как раньше.

**Non-Goals:**

- Производительность, трассировка, Session Replay, отзывы пользователей, сессии Release Health.
- Ошибки Worker'ов и Pages Functions: у них есть Workers Logs и `prod check` (спека `clone-monitoring`).
- Ошибки стенда `/engine-bench.html` и страниц без приложения.
- Зависание движка по таймауту: это не ошибка кода, а медленный маршрут; отдельное решение, если понадобится.

## Decisions

### SDK: `@sentry/react`, запуск до рендера, статический импорт

`main.tsx` вызывает `startErrorTracking(dsn)` из нового модуля `web/src/errors/` до `createRoot`, а `createRoot` получает `onUncaughtError` и `onRecoverableError` из `Sentry.reactErrorHandler()` (React 19 даёт эти колбэки у корня, отдельный Error Boundary не нужен). Глобальные `error` и `unhandledrejection` SDK ловит сам (интеграция `GlobalHandlers` по умолчанию).

- Импорт статический: самые важные ошибки — при запуске (пустая карта, WebGL), и динамический импорт SDK их бы пропускал. Цена — размер: SDK лёг в общий чанк `engine-*.js` (его делят приложение и стенд движка, страница грузит его сразу через `modulepreload`). Замер apply 2026-10-30, gzip: до — `index` 236.26 КБ + `engine` 2.15 КБ (деплой `e89ef337`), после — `index` 233.52 КБ + `engine` 36.39 КБ, то есть +31.5 КБ к коду приложения (≈ +13 %; с MapLibre 289 КБ и CSS 24 КБ — ≈ +6 % к загрузке страницы). Принято. Альтернатива — свой маленький буфер ранних ошибок до динамической загрузки SDK — сложнее, отклонена.
- Пустой DSN: `startErrorTracking` выходит до `Sentry.init`, обработчиков нет, запросов нет.
- Версия — `@sentry/react` 11.9.0 (apply 2026-10-30: 11.10.0 вышел за два дня до этого, взята версия недельной давности). В v11 `sendDefaultPii` заменён на `dataCollection`, и неуказанный `dataCollection` собирает всё, включая пользователя (IP), куки, заголовки и тела запросов (`MIGRATION.md` 11.x, «`sendDefaultPii` is replaced by `dataCollection`»). Поэтому каждая категория ставится явно: `userInfo`, `cookies`, `urlQueryParams`, `httpHeaders.request` и `.response`, `databaseQueryData`, `queues` — `false`, `httpBodies` — `[]`, `genAI` и `graphQL` — всё `false`.

### Что уходит и что вырезается

- `integrations`: из стандартных убирается `BrowserSession` (сессия на каждый заход — запрос без ошибки, против требования «Заход без ошибок»); трассировка и Replay не подключаются.
- `beforeSend`: адрес страницы в `request.url` и в `request` — только `origin + pathname`; `request.headers` и `request.query_string` удаляются. Это чистая функция в `web/src/errors/`, unit-тест на ссылках из фикстуры старых ссылок `src/state/fixtures/old-links.txt`.
- `beforeBreadcrumb`: остаются только `ui.click` и `ui.input` (селектор элемента, без значения поля). `fetch`, `xhr`, `navigation` и `console` отбрасываются целиком: в их адресах и текстах координаты, номера тайлов и треки. Обрезать адреса по частям ненадёжно (`/tiles/E40_N40.rd5`, путь тайла `z/x/y`), список разрешённых категорий надёжнее списка запрещённых.
- `allowUrls` — только скрипты своего origin: ошибки расширений браузера и чужих скриптов (Google Maps, CheerpJ с CDN) не тратят лимит. Ошибки CheerpJ доходят своим путём (ниже), не через стек чужого скрипта.
- `environment` — `production`; версию сборки задают Debug ID карт исходников (ниже), отдельный `release` не нужен.

### Отказ движка

`EngineOptions` в `engine.ts` получает необязательный колбэк `onBackendError(name, error)`; `startBackends` зовёт его в своём `catch` для каждого бэкенда. Колбэк трекера передаёт только синглтон приложения (`createEngine(defaultBackends(), …)` в том же файле); стенд `/engine-bench.html` и unit-тесты собирают движок без него, тест проверяет колбэк поддельными бэкендами без Sentry. Отчёт — `captureException` с тегом `engine.backend`.

- Повтор запуска при каждом клике отправлял бы один и тот же отказ снова: отчёт об отказе бэкенда — не чаще раза за загрузку страницы на бэкенд (набор отправленных имён в модуле трекера).
- `route-failed` не отправляется: это ответ роутера («маршрута нет»), он уже показан пользователю тостом (требование «Маршрута нет»).
- В воркер SDK не ставится: воркер без импортов, а его ошибки уже доходят до главного потока сообщением и событием `error`. Документированный путь Sentry для воркера (свой `Sentry.init` в воркере) требует импорта.

### Где хранится DSN

DSN не секрет — он попадает в бандл и виден любому. Секрет `SENTRY_DSN` нужен ради выключателя: сборка без него (форк, локальная, `check-web` до приёма заглушки) к Sentry не обращается. Схема — как у ключа Google: `VITE_SENTRY_DSN` только шагу `web build`, поле `sentryDsn` в `makeConfig`.

### Карты исходников: `sentry-cli` отдельным шагом, а не плагин Vite

Плагин `@sentry/vite-plugin` грузит карты из сборки, то есть токену пришлось бы быть в окружении `npm run build`, где исполняется код зависимостей, — против «Секреты только у шагов публикации». Поэтому в job `pages`:

1. `web build` с `build.sourcemap: 'hidden'` (карты рядом с файлами, без ссылки `sourceMappingURL` в бандле) — без токена.
2. `sentry-cli sourcemaps inject build` (точная версия через `npx`) — без токена: дописывает Debug ID в бандл и карты. Шаг идёт до e2e, чтобы e2e проверяли ровно то, что выкатится.
3. e2e.
4. `sentry-cli sourcemaps upload build` с `SENTRY_AUTH_TOKEN`, `SENTRY_ORG`, `SENTRY_PROJECT` — только если токен заведён.
5. `find build -name '*.map' -delete` и проверка, что карт нет, — всегда, до `wrangler pages deploy`.

Сборка `check-web` и локальная `npm run build` тоже дают карты; в `build/` они безвредны (не публикуются), но `check-no-author-hosts` и прочие проверки бандла не должны на них спотыкаться — проверить в apply.

### Тесты

- unit (Node): очистка события (`beforeSend`) на ссылках с `m=`, `nktk`, `nktl`, `r=`, `?` и `#`; фильтр хлебных крошек по категориям; повтор отказа бэкенда отправляется один раз.
- unit движка (`engine.test.ts`): `onBackendError` вызван для каждого упавшего бэкенда, не вызван при успешном запуске и при `route-failed`.
- unit «Сборка без DSN» (`errors/tracking.test.ts`, SDK подменён): без DSN `Sentry.init` и `captureException` не вызываются, `fetch` не тронут. Без `init` у SDK нет клиента и транспорта, так что этого достаточно; настоящее брошенное исключение в browser mode Vitest засчитал бы как упавший тест.
- e2e: заглушка приёма Sentry в `network` (`*.ingest.sentry.io` и регион `*.ingest.de.sentry.io` — ответ `200`, тела сохраняются, как `FAKE_GOOGLE_MAPS`); сценарии «Ошибка на странице» (исключение из `page.evaluate` через `setTimeout`, в конверте нет `#`, `m=`, координат и адресов запросов) и «Заход без ошибок» (открыть ссылку с треком — ноль конвертов). Без DSN в сборке эти тесты пропускаются (`test.skip` с причиной): локальная `npm run build` без секрета. В `check-web.yml` сборка получает поддельный DSN (`https://public@o0.ingest.sentry.io/0` — формат DSN, не секрет), чтобы e2e шли всегда; в деплое — настоящий, приём подменён той же заглушкой.

## Risks / Trade-offs

- [Лимит плана Developer — 5 тыс. ошибок в месяц] → одна массовая ошибка выберет лимит за день, остальные отчёты Sentry отбросит до конца месяца. Смягчение: `allowUrls`, отчёт о движке раз за загрузку; при нужде — `sampleRate` или фильтр в проекте Sentry. Риск — в backlog, «Внешние зависимости и риски».
- [DSN публичен] → кто угодно может слать в проект мусор и тратить лимит. Смягчение — фильтры входящих событий в настройках проекта Sentry (владелец), «Allowed Domains» проекта = `nakarte-routing.pages.dev`.
- [Чужой сервис получает данные пользователей] → стек, браузер, ОС, путь страницы и клики без значений; IP не собирается SDK (а сохранение IP на стороне Sentry владелец выключает в настройках приватности проекта). Координаты и треки вырезаны до отправки, и это проверяет e2e.
- [Размер бандла] → SDK добавляет к главному чанку; замер в apply. Если прирост окажется больше разумного, вернуться к решению про динамический импорт.
- [Пользователи из России с урезанным Cloudflare] → у них не загружается и сам бандл, трекер их не увидит; приём Sentry у них тоже может быть недоступен.
- [Карта утекла в публикацию] → проверка «в `build/` нет `*.map`» стоит перед `wrangler pages deploy` и валит деплой.

## Migration Plan

1. Владелец: аккаунт Sentry (план Developer), проект Browser JavaScript / React, Allowed Domains и выключенное хранение IP в настройках проекта; секреты GitHub `SENTRY_DSN` и `SENTRY_AUTH_TOKEN` (токен организации с правом загрузки карт), переменные `SENTRY_ORG` и `SENTRY_PROJECT`. Агент токены не вводит.
2. Код и workflow можно смержить до шага 1: без секретов деплой идёт как сейчас (требование «Секреты не заведены»).
3. После секретов — ручной `deploy pages`; проверка: в бандле прода есть DSN, `*.map` на проде нет, тестовое исключение из консоли браузера на проде видно в Sentry со стеком по исходникам и адресом без `#`.
4. Откат — удалить секрет `SENTRY_DSN` и выкатить: трекер выключен без правки кода.
