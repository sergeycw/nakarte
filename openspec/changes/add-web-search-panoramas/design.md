Результат без `bbox` — зум 17 старого клиента. Координаты и ссылки разбираются раньше поисковика (`magicProviders`); их случаи — karma-тесты [test_search_coordinates.js](../../../test/test_search_coordinates.js) и [test_search_links.js](../../../test/test_search_links.js).
- Ссылки: короткие `goo.gl/maps` и `mapy.com/s/` разворачиваются `HEAD` через прокси; итоговый адрес — адрес прокси (`xhr.responseURL`), и разбор работает на нём, потому что прокси оставляет путь и запрос цели. `mapy.com/s/favepemeko` через прокси отвечает `301` на `en.mapy.cz/...?x=…&y=…&z=…` (2026-10-09). Google отправляет запросы с IP прокси на капчу `google.com/sorry/` с исходным адресом в `continue` — старый код берёт адрес оттуда. Современные `maps.app.goo.gl/…` старый клиент не понимает; живой ссылки для проверки нет.
- Метка: `r=lat/lng/название` (`toFixed(6)`, `encodeURIComponent`), клик по карте мимо метки её убирает, клик по метке шлёт карте клик с `suggested: true` — постановка точки трека берёт название метки (`createNewPoint`). «Copy link» исключает `q` и `r` (`keysToExcludeOnCopyLink`); в новом приложении это уже так (`shareLink` в `tracks/share.ts`). `q=` — текст запроса поиска в адресе.
- Панорамы: один провайдер `google`, код `g`. `n2=_g` — режим включён, `n2=_g/g/lat/lng/heading/pitch/zoom` — с панорамой; старый `n=lat/lng/heading/pitch/zoom` переводится в `n2=` (`hashStateUpgrader`). Поиск — `StreetViewService.getPanorama({location, radius, preference: NEAREST})`, радиус — 24 px экрана в метрах. Окно — `StreetViewPanorama` с `enableCloseButton`, `imageDateControl`, без `motionTracking`; на смену позиции карта сдвигается, если точка ушла за край (`pad(-0.05)`); метка на карте поворачивается по `heading`. Старый код читает `pov.zoom`, а в `StreetViewPov` по [справке](https://developers.google.com/maps/documentation/javascript/reference/street-view) только `heading` и `pitch`, зум — `getZoom()`/`setZoom()`.
- Maps JavaScript API: старый грузит `https://maps.googleapis.com/maps/api/js?v=3&key=<ключ>` скриптом при первом клике в режиме; пустой ключ — режим без ключа, правила `keyless.css` включаются классом контейнера. По [справке загрузки](https://developers.google.com/maps/documentation/javascript/load-maps-js-api) `callback` — имя глобальной функции, которую API зовёт после загрузки. `getPanorama` возвращает и промис, но что он делает при `ZERO_RESULTS`, справка не говорит; форма с колбэком отдаёт статус явно. Тайл покрытия `maps.googleapis.com/maps/vt?…svv` отвечает без ключа, `200 image/png`, `Access-Control-Allow-Origin: *` — WebGL его возьмёт.
- Секрета `GOOGLE_MAPS_API_KEY` в репозитории нет (`gh secret list`, 2026-10-09): прод работает без ключа.
- Внешние карты (проверено `curl` 2026-10-09): Google, OSM, Google Earth, `mapy.com`, Wikimapia, Meteoblue — `200`; Яндекс — `302` на региональный домен; `en.mapy.cz/turisticka` — `301` на `mapy.com/en/turisticka`. Зумы старого клиента — Leaflet (256 px), пределы по сервису; Google Earth берёт высоту центра из API высот (без ответа — 8000 м).
- Геолокация старого: состояния «выкл / ищет / включено / следует», следование выключается движением карты, `watchPosition` с `enableHighAccuracy: true`, последнее положение — `localStorage.leaflet_locate_position` (`{lat, lon}`); при заходе без `m=` и без треков в адресе карта встаёт на него и делает `getCurrentPosition` с таймаутом 500 мс (только если положение уже запомнено). Сообщения ошибок — `locationErrorMessage` в `App.js`.
- Отметки расстояния — `L.MeasuredLine`: на каждый отрезок отдельно от его начала, шаг — первый из `500, 1000, 2000, 5000 … 1 000 000` м не меньше 15 мм экрана (96 dpi, масштаб в центре трека), подпись `round(d/10)/100 km`, повёрнута вдоль звена; последняя регулярная отметка ближе полинтервала к концу убирается, `0` — если отрезок длиннее полинтервала, конец — всегда. Пересчёт на `zoomend` и `moveend`, только в видимой части карты.
- Линейка — `addTrackAndEdit('Ruler').measureTicksShown(true)` и раскрытие списка треков.

## Goals / Non-Goals

**Goals:**
- Разбор координат, ссылок, ответов поисковиков, адреса `r=` и `n2=`, отметок расстояния и адресов внешних карт — чистые функции без карты и React, покрытые unit-тестами; случаи karma-тестов старого клиента переносятся как есть.
- Maps JavaScript API — только по требованию и за своим интерфейсом: browser-тесты и e2e его подменяют, в Google не ходят.
- Всё работает на телефоне 390×844 вместе с профилем высот и панелью редактора.

**Non-Goals:**
- `q=` (текст запроса в адресе): новое приложение его не пишет и не читает, параметр остаётся в адресе как есть.
- Провайдеры панорам кроме Google, Яндекс Панорамы (backlog), свой ключ Google — шаги владельца в backlog.
- Иконки категорий mapy.cz, журнал событий поиска (`logEvent`) — не переносятся.
- Вид панелей — change `polish-web-ui`.

## Decisions

Решения, которых нет в ресёрче, архивах и задаче change, помечены **[агент]**: владелец попросил не останавливаться на вопросах, они ждут его подтверждения. Замечания владельца по скриншотам — сюда как **[владелец]**.

### Один change, а не два **[агент]**

Ресёрч оценил change в 2–3 дня; разрез «поиск, метка, внешние карты, геолокация» и «Street View, линейка» напрашивается. Не режем: обе половины трогают одни и те же места — группа кнопок карты справа, разбор адреса в `sync.ts` (`r=` и `n2=`), арбитраж клика по карте в `MapEditor` (метка, панорама, редактор), нижние панели и `--bottom-inset`. Два change правили бы их дважды, и change переключения ждёт оба. Работа идёт по частям с отдельными коммитами и зелёными тестами на каждой; ревью — одно на весь дифф.

### Модули

- `web/src/search/`: `coordinates.ts` (порт `CoordinatesProvider`), `links.ts` (порт `LinksProvider`, короткие ссылки — через `fetch` и адрес прокси), `mapycz.ts` и `photon.ts` (запрос и разбор ответа — отдельными функциями), `search.ts` (выбор: ссылка → координаты → mapy.cz → photon), `SearchBox.tsx` (строка и результаты), `placemark.ts` (`r=`) и `PlacemarkOnMap.tsx` (метка на карте). Результат — `{ title, subtitle, latlng, bounds | null, zoom | null }`, зум в единицах MapLibre.
- `web/src/streetview/`: `api.ts` (интерфейс `StreetViewApi` — поиск панорамы и создание окна), `google.ts` (реализация на Maps JavaScript API, загрузка по требованию, `keyless.css`), `coverage.ts` (адрес тайлов покрытия, без импортов — его читает и e2e), `hash.ts` (`n2=`/`n=`), `controller.ts` (поиск по клику, устаревшие ответы, тост), `StreetViewPanel.tsx`, `StreetViewOnMap.tsx` (метка направления).
- `web/src/map/`: `external.ts` (адреса внешних карт), `MapButtons.tsx` (Street View, линейка, внешние карты, номер зума — контрол MapLibre справа), `locate.ts` (запомненное положение).
- `web/src/tracks/ticks.ts` — отметки расстояния; слой — в `tracks/style.ts`.

Стор: `placemark: { lat, lng, title } | null`; `streetView: { enabled: boolean; pano: PanoView | null; request: { view: PanoView; seq } | null }`, где `PanoView = { lat, lng, heading, pitch, zoom }` — `pano` пишет окно панорамы при каждой смене позиции и взгляда, `request` — что окну показать (клик по карте, адрес). Так же устроены `view`/`viewRequest` карты.

### Поиск по названию: mapy.cz, запасной — photon **[агент]**

Ресёрч пишет «photon, mapy.cz», backlog считает photon главным; на деле старый клиент ищет только в mapy.cz (Context). Оставляем mapy.cz главным: у него лучше результаты по местам вне Европы (проверка 2026-10-09 по «mtatsminda»: парк, район, вершина с категориями) и категории на языке запроса, а у старого клиента пользователи привыкли к его выдаче. photon — запасной путь при ошибке mapy.cz (прокси лёг, mapy.cz сменил API): он без прокси и без ключа, CORS `*`. Сразу оба не спрашиваем — лишняя нагрузка на чужой бесплатный сервис. Подпись под результатами — того, кто ответил. Пункт рисков backlog исправляется.

- Задержка ввода — 400 мс от последнего нажатия, прежний запрос отменяется `AbortController`, ответ на устаревший запрос отбрасывается сравнением номера запроса.
- mapy.cz: параметры старого (`phrase`, `lat`, `lon`, `zoom` старого клиента, `lang`, `count=5`), результаты `suggestSecondRow === 'Poloha'` выбрасываются, как у старого. Подзаголовок — `suggestSecondRow` (категория и адрес): таблица категорий старого (`categories.csv`) и иконки не нужны **[агент]** — вторая строка уже несёт категорию на языке `lang`, иконки — внешний запрос на каждый результат.
- photon: `q`, `limit=5`, `lang` — первый язык браузера из `en de fr it`, иначе `en` (старый вычислял язык, но слал `en` — расхождение исправляем) **[агент]**, `lat`/`lon` центра. Подзаголовок — категория (`osm_value`, для `yes` — `osm_key`) и адрес.
- Ошибка: `Search failed: <причина>` после неудачи обоих; причина — `network error` или `HTTP <код>`.

### Координаты и ссылки

Порт старого кода как есть, на TypeScript, без Leaflet: регулярные выражения, нормализация ввода, форматирование подписи. Тест — случаи karma-тестов старого клиента целиком, плюс неверные. Разница одна: зум результата — в единицах MapLibre (старый зум − 1), как везде в новом приложении (`AGENTS.md`, подвох про зум). Короткие ссылки: `fetch(<прокси>/<схема>/<хост>/<путь>, { method: 'HEAD' })`, итоговый адрес — `response.url` (браузер идёт по редиректам прокси); из него снимается префикс прокси, капча Google разворачивается по `continue`. `maps.app.goo.gl` не добавляем: без живой ссылки поведение прокси на нём не проверить — пункт backlog.

### Где живёт строка поиска **[агент]**

В панели с названием (`InfoPanel`), под названием: на телефоне колонка слева и так узкая, отдельная карточка заняла бы ещё строку. Результаты — списком под строкой внутри той же карточки (не всплывающим окном: на телефоне всплывающее окно над картой закрыло бы те же места, а список в колонке прокручивается вместе с ней). Список виден, пока у строки фокус; клавиши — стрелки, Enter, Escape (как `onKeyDown` старого). Alt+L — `KeyboardEvent.code === 'KeyL'`: на macOS Alt меняет `key`.

### Метка

Метка — `Marker` react-maplibre (DOM, как спиннер ожидающего отрезка): точка и подпись с названием. Клик по карте убирает метку — в `MapEditor.onClick`, где уже решается, кому достался клик, — кроме кликов рисования линии и постановки точек и выбора Join/Shortcut **[агент]**: у старого метку снимал любой клик, и линию к найденному месту нельзя было довести — первая же опорная точка метку убирала (выяснилось в browser-тесте). Клик по самой метке в двух её режимах: родные `mousedown`/`click` элемента метки гасятся `stopPropagation` (до холста карты события не доходят; обработчик React для этого опоздал бы — React слушает корень приложения), затем:

- постановка точки трека (`pointTool: add`) — точка в координатах метки с её названием (`addPoint` получает необязательное название);
- рисование линии — опорная точка в координатах метки (`editing.click`, копия мира — ближняя к линии, как у клика по карте);
- в остальных режимах события метки не гасятся и клик уходит карте, как у старого (клик по метке — клик карты с `suggested`): метка снимается, в режиме Street View ищется панорама, Move переносит точку туда (ревью).

`r=` в `sync.ts`: читается при старте и на `hashchange`, пишется сразу на смену метки (не с задержкой, как `m=`), отсутствие метки — нет параметра. Формат — старого клиента байт в байт: `toFixed(6)` и `encodeURIComponent` названия; разбор — проверки `unserializeState` старого (широта ±90, долгота ±180, название может отсутствовать).

### Street View: режим, клик, окно

- Покрытие — растровый источник `street-view-coverage` (256 px, `maxzoom` 21) в стиле, только когда режим включён, слоем над слоями каталога и под профилем, треками и редактором (`rasterOverlay` старого — `zIndex` 300 под оверлеями треков). Ошибка его тайлов идёт в общий тост ошибок тайлов с названием `Street View coverage`.
- Клик: в `MapEditor.onClick` до логики редактора — если режим включён и клик не занят (не подавлен после перетаскивания, нет меню, `pointTool`, `lineTool` и рисования, не по точке трека и не по опорной точке — у них своё меню), панорама ищется в точке клика с радиусом 24 px в метрах на широте клика. Редактор после этого работает как обычно: клик по треку начинает его правку, мимо — заканчивает, как у старого, где оба обработчика клика независимы **[агент]**. Арбитраж в одном месте: отдельный слушатель `click` видел бы состояние уже после того, как редактор его поменял (например, `pointTool` сбрасывается переносом точки).
- Поиск — `StreetViewApi.findPanorama(latlng, radius)` → точка панорамы или `null`; устаревший ответ (пришёл после нового клика или выключения режима) отбрасывается. Найдено — `request` с этой точкой, `heading` — прежний взгляд, `pitch` 0, `zoom` 1 (`showPano` старого).
- Окно: `StreetViewApi.createViewer(container, { onChange })` → `{ show(view), resize(), destroy() }`. Панель берёт окно при первом открытии и держит, пока режим включён: закрытие прячет панель (CSS), выключение режима зовёт `destroy`. `StreetViewPanorama` Google уничтожить нельзя, поэтому у `google.ts` окно одно на страницу в своём `div`: `createViewer` переносит его в контейнер новой панели, `destroy` прячет и вынимает из документа, а вызов от устаревшего владельца (второй эффект StrictMode, выключенный режим) ничего не делает (ревью: новое окно на каждое включение режима копило бы WebGL-сцены, а лимит контекстов у браузера общий с картой). Смена позиции окна → `pano` в сторе → метка на карте; уход точки за край видимой части (5 %) → `easeTo` карты.
- Метка направления — `Marker` с `rotation` = `heading` и `rotationAlignment: 'map'`.

### Панель панорамы **[агент]**

Снизу на всю ширину, над профилем высот, если он открыт: высота `min(45dvh, 28rem)`, с открытым профилем — `min(30dvh, 20rem)` (скриншоты 2026-10-09: обе панели в полный рост оставляли телефону ≈ 100 px карты, а кнопки карты справа уходили под панель). `--bottom-inset` становится суммой нижних панелей (профиль + панорама + отступы), панель панорамы стоит над профилем по высоте профиля. Вычисление — один компонент `BottomInset` в `App`: он уже знает про профиль. На телефоне 390×844 с обеими панелями над ними остаётся ≈ 330 px карты — пользователь сам открыл обе, а закрытие любой возвращает место. Взаимоисключение (панорама закрывает профиль) отвергнуто: профиль теряет выделение и курсор, а смотреть панораму вдоль профиля — ровно тот случай, ради которого они нужны вместе. Сбоку (как разбивка 50/50 старого): на телефоне всё равно снизу, а на компьютере правая колонка занята переключателем слоёв и кнопками карты — две раскладки на одну функцию ради «полировки» не нужны сейчас. Перетаскиваемой границы старого (`splitter`) нет — пункт для `polish-web-ui`.

### Maps JavaScript API и ключ

`google.ts` грузит `https://maps.googleapis.com/maps/api/js?v=3&key=<ключ>&callback=<имя>` один раз на страницу (промис — модульный синглтон, как `getGoogle` старого): тот же адрес, что у старого клиента, плюс документированный `callback` вместо события `load` тега. `loading=async` не добавляем: с ним `google.maps.StreetViewPanorama` доступен только через `importLibrary`, а поведение режима без ключа с ним не проверено. Ошибка загрузки (тег `error`, нет `google.maps` после колбэка, нет ответа 20 с) — промис отклоняется и сбрасывается; поиск без ответа 10 с — та же ошибка, следующий клик пробует снова; тост `Street View is unavailable`.

Ключ — `import.meta.env.VITE_GOOGLE_MAPS_API_KEY ?? ''` в `config.ts` (`googleMapsApiKey`). В `deploy-pages.yml` шаг `web build` получает `VITE_GOOGLE_MAPS_API_KEY: ${{ secrets.GOOGLE_MAPS_API_KEY }}` — **тот же секрет**, что у старого клиента, отдельного не заводим **[агент]**: ключ один на сайт, ограничения по referrer и API в Google Cloud у него общие. Тесты идут без ключа (`npm test` — отдельный шаг без `env`), `check-web.yml` не меняется. e2e в деплое гоняет ту же сборку `build/next/`, что собрана с ключом, поэтому ключ e2e берёт из адреса загрузки API, а правила режима без ключа ждёт только при пустом (ревью: жёсткое `key=` уронило бы деплой, как только владелец заведёт секрет). Пустой ключ — класс `google-street-view-keyless` на контейнере окна и правила `keyless.css` старого клиента, перенесённые в `streetview/keyless.css` с той же шапкой (решение владельца — архив `hide-street-view-dev-overlay`). Свои типы на используемую часть API (`StreetViewPanorama`, `StreetViewService`, события) вместо `@types/google.maps` **[агент]**: нужны пять методов, а интерфейс `StreetViewApi` всё равно отделяет приложение от Google.

### Street View в адресе

`streetview/hash.ts`: разбор `n2=` — первый элемент начинается с `_` и содержит `g` → режим включён; дальше `g` и пять чисел → панорама (неверные числа — режим без панорамы). Старый `n=`: значения — панорама, без значений — только режим; после чтения `n=` стирается, пишется `n2=`. `n2=_w`, `n2=wmc` — режим выключен (спека). Запись: смена режима и открытие — сразу, движение взгляда — не чаще раза в 300 мс (как `m=`), формат — `toFixed(6)` координат и `toFixed(1)` углов и зума, как `getState` старого.

### Внешние карты

`map/external.ts` — список старого клиента; адрес mapy.cz заменён на конечный `https://mapy.com/en/turisticka?x=…&y=…&z=…` (старый отвечает `301` туда). Зум — `round(MapLibre + 1)` в пределах сервиса. Meteoblue — формат старого (`{lat}N{lng}E` со знаком, комментарий автора). Google Earth — высота центра из `fetchElevations` (`elevation/api.ts`) с таймаутом 2 с, иначе 8000 м, расстояние камеры — формула старого. Открытие — `window.open(url, '_blank', 'noopener')`; у Google Earth после ожидания высоты: браузер разрешает `window.open` в пределах временной активации после клика, ответ API высот укладывается в неё — проверка на проде.

Меню — `DropdownMenu` shadcn у кнопки в группе кнопок карты, заголовок `Open this place in`.

### Кнопки карты справа **[агент]**

Справа сверху уже стоят кнопка слоёв и кнопки зума MapLibre. Ниже в том же столбце — контролы MapLibre: геолокация (`GeolocateControl`), затем своя группа (`useControl` react-maplibre с порталом React в контейнер контрола): Street View (`BinocularsIcon`), «Measure distance» (`RulerIcon`), внешние карты (`ExternalLinkIcon`). Номер зума — свой контрол между кнопками зума и геолокацией: текст `round(zoom + 1)`, обновляется на `zoom`. Масштаб — `ScaleControl` MapLibre слева снизу (над `--bottom-inset`, как атрибуция). Так кнопки не спорят с левой колонкой (поиск и треки) и с нижними панелями.

### Геолокация: `GeolocateControl` MapLibre **[агент]**

Машина состояний старого (`OFF → WAITING → ACTIVE_LOCK ⇄ BACKGROUND`, движение карты выключает следование, повторное нажатие возвращает, следующее выключает) совпадает с `GeolocateControl` MapLibre 6 с `trackUserLocation: true` (`src/ui/control/geolocate_control.ts`): точка и круг точности, события `geolocate`, `error`. Свой контрол повторил бы ≈ 400 строк старого. Параметры: `positionOptions: { enableHighAccuracy: true, timeout: 30 000 }` (у MapLibre по умолчанию 6 с — на телефоне первый фикс GPS дольше; у старого таймаута не было), `fitBoundsOptions.maxZoom: 16` (`maxAutoZoom` 17 старого в зуме MapLibre). Ошибки — событие `error` → тост с текстами старого (`code` 1, 2; нет `navigator.geolocation` — 0; иначе `Geolocation error: …`). Расхождение: если разрешение уже запрещено, MapLibre при создании делает кнопку неактивной с подсказкой `Location not available` и не зовёт браузер — тоста тогда нет; кнопка не пропадает, подсказка видна при наведении.

Запомненное положение — `map/locate.ts`: ключ `nakarte-web:position` (`{lat, lng}`), при чтении — откат на `leaflet_locate_position` старого клиента (тот же origin) **[агент]**. Пишется на каждое событие `geolocate`, стирается на `error` с кодом 1. Заход: если в адресе нет годного `m=` и нет параметров треков, а положение есть — начальный вид с центром в нём и зумом по умолчанию, затем `getCurrentPosition` с таймаутом 500 мс и `requestView` при ответе (как `moveMapToCurrentLocation`).

### Отметки расстояния и линейка

`tracks/ticks.ts`: `minTickInterval(zoom, lat)` (15 мм при 96 dpi в метрах на широте середины отрезка, `getBounds().getCenter()` старого), `tickStep` (ряд шагов старого) и `segmentTicks(points, minInterval)` → `{ lat, lng, distance, rotate }[]` — алгоритм `getTicksPositions` старого: точка по прямой между узлами, последняя регулярная отметка убирается, если до конца меньше половины 15 мм (а не полшага), `0` — если отрезок длиннее этой половины. Подпись — поперёк линии, как у старого: угол — матрица `transformMatrix` старого по звену в проекции Меркатора, переведённая в `text-rotate`, текст с отступом 0.7 em от линии. Зум — `floor(zoom)`: шаг меняется ступенями, а не на каждом кадре, и на дробном зуме отметки не ближе 15 мм (ревью: `round` давал ≈ 10.6 мм на зуме x.5). Без отметок источник — один и тот же пустой объект: стиль не пересобирается на каждой ступени зума.

На карте — GeoJSON-источник `track-ticks` и символьный слой над линиями треков: `text-field` подпись, `text-rotate` угол, `text-rotation-alignment: map`, `text-allow-overlap` и `text-ignore-placement` (как у старого, отметки видны все и не вытесняют подписи точек; поверх подписи точки отметка может лечь). Источник собирает `BaseMap` из видимых треков с `measureTicksShown` и целого зума, мемоизировано; в видимую часть карты не обрезаем **[агент]**: шаг ограничен снизу 500 м, трек 1 000 км — 2 000 подписей, MapLibre их держит, а обрезка по видимой части требует пересборки на каждом сдвиге. Редактируемый отрезок отметки тоже имеет: у старого их отключение на время правки закомментировано (`editingstart` в `track-list.js`), а линейка без отметок во время рисования бесполезна.

Меню трека — флажок `Show distance marks` (`DropdownMenuCheckboxItem`); `updateTrack` получает поле `measureTicksShown`, автосохранение его уже пишет.

«Measure distance» — `editing.newTrack('Ruler')` с `measureTicksShown: true` (новый необязательный параметр). Раскрытие свёрнутого списка треков (`setExpanded` старого) не переносим **[агент]**: состояние свёрнутости — локальное в `TrackList`, а трек `Ruler` и так виден на карте вместе с отметками и длиной.

## Risks / Trade-offs

- [photon и mapy.cz — чужие бесплатные сервисы без гарантий] → два независимых пути; координаты и ссылки работают без них.
- [Режим без ключа Google против условий и может закрыться] → решение владельца в архивах; ключ — тот же секрет, деплой подставит его и новому приложению.
- [Правила `keyless.css` завязаны на вёрстку Google] → те же, что у старого клиента; проверка на проде после деплоя глазами (скриншот).
- [Окно Google живёт, пока включён режим, и держит память] → замер `phys_footprint` — «Проверки»; выключение режима снимает контейнер.
- [`window.open` после ожидания высоты для Google Earth может заблокироваться] → таймаут 2 с; проверка на проде.
- [Обе нижние панели на телефоне оставляют ≈ 330 px карты] → каждая закрывается одной кнопкой; раскладка — `polish-web-ui`.
- [Столбец кнопок карты справа (≈ 310 px от верха) не учитывает `--bottom-inset`: в низком окне (телефон в альбомной ориентации, высота < ≈ 600 px) Street View, линейка и внешние карты уходят под панель панорамы] → панель закрывается своей кнопкой; раскладка — `polish-web-ui`.
- [Геолокация, запрещённая раньше: кнопка неактивна без тоста, подсказка только при наведении — на телефоне её не увидеть] → поведение `GeolocateControl` MapLibre, спека это фиксирует («Геолокация недоступна»); объяснение по нажатию — `polish-web-ui`.
- [Решения **[агент]** без подтверждения владельца] → вынесены в заголовки и пункты, правка — мелкий change.

## Проверки

### Память с окном Google

2026-10-09, Playwright 1.64, Chromium headless, профиль `Pixel 7`, dev-сервер (8769), настоящий Maps JavaScript API без ключа, Тбилиси `m=17/41.6995/44.7976` (проспект Руставели). `phys_footprint` — сумма `footprint` по дереву процессов браузера (`launchServer`, `pgrep -P`), перед каждым замером — сборка мусора через CDP и 2 с паузы. Скрипт вне репозитория, два прогона.

| момент | phys_footprint, МБ |
|---|---|
| карта | 291–294 |
| режим включён, покрытие | 301–304 |
| панорама открыта | 379–382 |
| панорама закрыта | 330–332 |
| режим выключен, окно уничтожено | 329–332 |

После исправлений ревью (одно окно на страницу) — три цикла «режим включён → панорама → режим выключен» в одной вкладке: 385, 365, 363 МБ с открытой панорамой и 382, 364, 360 МБ после выключения; `.gm-style` в документе всегда один — память от циклов не растёт.

Окно Google — ≈ +80 МБ, после закрытия остаётся ≈ +40 МБ: скрипт API (≈ 5 запросов, `maps-api-v3`) выгрузить нельзя, а `destroy` снимает слушатели и прячет окно. Режим без панорамы стоит ≈ +10 МБ (тайлы покрытия). API грузится только при первом поиске — на заходе без Street View его нет.

**Подвох:** снимки панорамы (`lh3.googleusercontent.com/gpms-cs-s/…`) на `Referer: http://localhost:8769/` отвечают `429`, с `Referer: https://nakarte-routing.pages.dev/` — `200` (проверено `curl` 2026-10-09). Локально окно пустое (метаданные, стрелки и подписи есть, снимков нет) — в замере выше нет текстур снимков, его надо повторить на проде. Старый клиент на проде той же панорамой рисует снимок (скриншот headless с `--use-angle=metal`). Правила `keyless.css` при этом работают: без класса видны «For development purposes only» и окно ошибки Google, с классом — нет.
