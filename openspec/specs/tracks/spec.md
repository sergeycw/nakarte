# tracks Specification

## Purpose
Треки нового приложения клона: список треков поверх карты и действия с ним, отрисовка треков на карте, треки из параметров адреса старого клиента и ссылка на треки через хранилище клона.

## Requirements

### Requirement: Список треков поверх карты

Новое приложение SHALL показывать поверх карты список треков: у каждого трека — флажок видимости, цвет, название и длина всех его отрезков в километрах (два знака до 10 км, один — до 100 км, без дробной части дальше, как в старом клиенте). Клик по названию SHALL показывать трек целиком. Список SHALL сворачиваться, чтобы не закрывать карту.

#### Scenario: Трек в списке

- **WHEN** открыт трек из двух отрезков общей длиной 12 345 м
- **THEN** в списке есть строка с его названием, цветом, отмеченным флажком и длиной `12.3 km`

#### Scenario: Показать трек целиком

- **WHEN** пользователь кликает по названию трека, который не виден на карте
- **THEN** карта переходит так, что трек виден целиком

### Requirement: Треки на карте

Видимые треки SHALL рисоваться на карте поверх всех слоёв: отрезки — линиями цвета трека, точки — метками цвета трека с подписью-названием. Скрытый трек SHALL NOT рисоваться. Цвет трека SHALL выбираться из шести цветов старого клиента (`#77f`, `#f95`, `#0ff`, `#f77`, `#f7f`, `#ee5`); новые треки получают их по кругу.

#### Scenario: Скрыть трек

- **WHEN** пользователь снимает флажок видимости трека
- **THEN** линии и точки трека пропадают с карты, трек остаётся в списке

#### Scenario: Сменить цвет

- **WHEN** пользователь выбирает треку другой цвет
- **THEN** линии и точки трека на карте перекрашиваются

#### Scenario: Трек над слоями

- **WHEN** включены подложка и оверлеи
- **THEN** линии и точки треков лежат над всеми слоями карты

### Requirement: Действия с треком

Для каждого трека SHALL быть доступны: переименовать, дублировать (копия с тем же названием, отрезками и точками), развернуть (каждый отрезок в обратном порядке точек), удалить, сохранить в GPX и KML (capability `track-files`), скопировать ссылку на трек.

#### Scenario: Переименовать

- **WHEN** пользователь вводит новое непустое название трека
- **THEN** название меняется в списке; пустое название трек не меняет

#### Scenario: Развернуть

- **WHEN** пользователь разворачивает трек
- **THEN** первая точка каждого отрезка становится последней, длина трека не меняется

#### Scenario: Дублировать

- **WHEN** пользователь дублирует трек
- **THEN** в списке появляется второй трек с тем же названием, отрезками и точками

### Requirement: Действия со списком

Список SHALL позволять: создать новый трек (название — из поля ввода ссылки, если оно не пусто, иначе `New track`), удалить все треки, удалить скрытые треки, создать новый трек из всех видимых (их отрезки и точки в одном треке), скопировать ссылку на все и на видимые треки, сохранить все треки в ZIP.

#### Scenario: Удалить скрытые

- **WHEN** в списке три трека, один из них скрыт, и пользователь выбирает «Delete hidden tracks»
- **THEN** в списке остаются два видимых трека

#### Scenario: Новый трек из видимых

- **WHEN** видимы два трека по одному отрезку и пользователь создаёт новый трек из видимых
- **THEN** появляется трек с двумя отрезками и точками обоих треков

### Requirement: Треки из старых ссылок

Новое приложение SHALL открывать треки из параметров адреса старого клиента: `nktk=` (строки версий 1–4, несколько через `/`), `nktl=` (ключи хранилища треков клона), `nktu=` (закодированные ссылки на треки, capability `track-files`), `nktp=` (точка `lat/lng/название`), `nktj=` (base64 JSON со списком треков, точек и ссылок). Цвет, видимость и флаг отметок расстояния из ссылки SHALL сохраняться в треке. Испорченный параметр SHALL давать сообщение об ошибке, а не падение приложения.

#### Scenario: Ссылка на хранилище

- **WHEN** приложение открыто по адресу `#nktl={key}`, и хранилище отвечает `200` со строкой треков
- **THEN** треки появляются в списке и на карте, `nktl=` уходит из адреса

#### Scenario: Трек в адресе

- **WHEN** приложение открыто по ссылке старого клиента с `nktk=` версии 1, 2, 3 или 4
- **THEN** трек открывается с названием, отрезками, точками, цветом и видимостью из ссылки

#### Scenario: Неизвестный ключ

- **WHEN** хранилище отвечает `404` на ключ из `nktl=`
- **THEN** показано сообщение об ошибке загрузки, приложение работает

#### Scenario: Точка в адресе

- **WHEN** приложение открыто по адресу `#nktp=41.7/44.8/Tbilisi`
- **THEN** в списке трек `Tbilisi` с одной точкой `Tbilisi`

### Requirement: Параметр трека уходит из адреса

После загрузки параметр трека SHALL уходить из адреса, остальные параметры — оставаться на местах, как в старом клиенте. Если в адресе нет годного `m=`, карта SHALL показать загруженные треки целиком. Параметр трека, добавленный в адрес без перезагрузки, SHALL открываться так же.

#### Scenario: Ссылка без вида

- **WHEN** приложение открыто по адресу `#nktk=…&l=O` без `m=`
- **THEN** карта показывает трек целиком, в адресе остаются `l=O` и новый `m=`, `nktk=` нет

#### Scenario: Ссылка вставлена в адрес

- **WHEN** в открытом приложении пользователь дописывает в адрес `&nktp=41.7/44.8/Tbilisi`
- **THEN** в списке появляется трек `Tbilisi`

### Requirement: Ссылка на треки после ответа хранилища

«Copy link» SHALL сначала сохранять треки в хранилище клона (`POST /track/{key}`, ключ — base64url от md5 тела, тело — строки `nktk` версии 4 через `/`) и SHALL отдавать ссылку `nktl={key}` пользователю только после ответа `200`. Ссылка SHALL содержать текущий адрес приложения без `q=` и `r=` и с `nktl=`. Ошибка хранилища SHALL давать сообщение `Error making link: …` без ссылки; ответ `413` — `Error making link: track is too big`. Без треков SHALL показываться `No tracks to copy`.

#### Scenario: Ссылка готова

- **WHEN** пользователь нажимает «Copy link for all tracks», и хранилище отвечает `200`
- **THEN** ссылка с `nktl=` попадает пользователю (буфер обмена или окно со ссылкой) только после ответа хранилища, и по ней открываются те же треки

#### Scenario: Хранилище недоступно

- **WHEN** хранилище отвечает ошибкой или недоступно
- **THEN** показано `Error making link: …`, ссылки пользователь не получает

#### Scenario: Слишком большой трек

- **WHEN** хранилище отвечает `413`
- **THEN** показано `Error making link: track is too big`
