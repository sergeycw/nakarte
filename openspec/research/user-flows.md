# Флоу использования и правки UI

Разговор с владельцем 2026-10-10: основные флоу приложения, где они спотыкаются и какие правки UI из них следуют. Changes нарезаны в [таблице](#changes-по-порядку); сделан change 1 — [layout-three-zones](../changes/archive/2026-10-10-layout-three-zones/design.md). Решения владельца помечены **[владелец]**, предложения агента, которые владелец не обсуждал, — **[агент]**. Каждый change переносит свои решения в свой design, и реестр `docs/architecture/decisions.md` ссылается уже на него; этот документ остаётся планом и справкой.

«Как сейчас» — `master` `580fa6c` (раскладка 4a, архив [polish-web-ui](../changes/archive/2026-10-10-polish-web-ui/design.md#макет-4a-владелец)) и кадры 2026-10-10 вне репозитория: `~/Desktop/nakarte-screenshots/desktop/` и `phone/` (скрипт — `tools/shots.mjs` там же). Номера кадров ниже — имена файлов.

## Кто и зачем

Продукт — **планирование маршрута дома за компьютером** **[владелец]**. Турист открывает сайт, чтобы проложить маршрут по тропам, оценить длину и набор, отдать GPX в часы или навигатор и ссылку друзьям. Телефон на тропе — редкий случай: на телефоне приложение должно открываться и не ломаться (это уже требует спека `web-client`, сценарий «Окно телефона»), отдельной раскладки под него сейчас не делаем (раздел [Телефон](#телефон)).

Главный принцип UI остаётся прежним — красиво, просто, понятно ([record-ui-decisions](../changes/archive/2026-10-08-record-ui-decisions/design.md)). Боль владельца с текущим видом: «грязный интерфейс, много крупных элементов» **[владелец]**.

### F1. Спланировать маршрут

Шаги сейчас:

1. Найти район: поиск в верхней строке или зум; слои — кнопкой справа сверху, поповер (`17-layer-switcher`).
2. `+ New` — сразу рисование, трек называется `New track`.
3. Активность — `Hiking ▾` в строке редактора; та же настройка — иконкой в шапке списка треков (`08-routing-menu`).
4. Клики по карте, перетаскивание точек, Backspace, Undo/Redo.
5. Профиль — кнопка `Elevation profile` снизу справа, панель живёт во время правки (`31-route-editor-with-profile`).
6. Правка куска — правый клик по линии или точке: Cut, Shortcut, Reverse… (`28a-map-menu-line`).
7. Точки (вода, ночёвка) — `Done` → `Tracks` → меню трека → `Add point` → отдельный режим (`22-add-points-panel`).
8. Название — `Done` → `Tracks` → меню трека → `Rename`: в строке редактора имя не правится (`EditPanel.tsx`).
9. Варианты — `Duplicate` в меню трека, флажки видимости.
10. Отдать — меню трека → `Save as GPX` / `Copy link for track` (`04-track-menu`).

Где спотыкается:

- Интерфейс шумный: подписанные кнопки (`Elevation profile`, `Measure distance`, `Street View`, `Tracks 3`, `+ New`) занимают углы карты **[владелец]**.
- Слои спрятаны в поповер, а при планировании их переключают постоянно **[владелец]**.
- Номер зума между `+` и `−` — место без пользы **[владелец]**.
- Название и экспорт — три уровня вложенности после `Done`, хотя это финал каждого планирования.
- Кнопка профиля берёт трек по правилу «редактируемый, иначе с открытым профилем, иначе первый видимый» (спека `tracks`, «Кнопка профиля высот», `MapActions.tsx`) — какой трек покажется без правки и без профиля, не очевидно.

### F3/F5. Чужой трек

Шаги сейчас: ссылка `nktl=`/`nktk=` открывается сама; ссылка на сайт (OSM, Яндекс, SportsTracker…) — `Tracks` → поле `Track URL`; файл — `Tracks` → иконка папки или перетаскивание на карту. Правка — клик по линии (начинает редактирование, спека `route-editing`), инструменты — правым кликом.

Где спотыкается:

- Два поля для ссылок: поиск понимает ссылки на места, но не на треки, поле `Track URL` спрятано в списке.
- Cut, Shortcut и Join есть только в контекстном меню. Владелец проблемы не видит **[владелец]**: правый клик на карте естественен, в changes не берём.

### F4. Поделиться

`Copy link for track` и `Save as GPX`/`KML` — в меню трека, `Copy link for all/visible tracks` и ZIP — в меню списка (`05-tracks-list-menu`). Боль та же, что в F1, шаг 10: экспорт далеко от только что проложенного маршрута.

### F7, F8. Street View и линейка

Обе кнопки — в строке снизу справа с подписями. По смыслу Street View — слой покрытия с выбором точки, линейка — рисование линии, как новый маршрут: трек `Ruler` с отметками расстояния (спека `tracks`, «Линейка»).

## Раскладка: три зоны

Решения владельца 2026-10-10. Референс вида — Apple Maps на macOS (скриншот владельца 2026-10-10): стекло, иконки без подписей, кнопки сгруппированы в вертикальные капсулы справа (слои и «где я» — одна капсула, зум `+`/`−` без номера — вторая), масштаб — тонкой полосой. Эскиз — цель после change `layer-thumbnails`; в `layout-three-zones` справа сверху — прежняя кнопка слоёв.

```
+--------------------------------------------------------------+
| ( Q search or paste a track link ) (=) (+) (ruler)   (Topo)  |
|                                                      (Sat )  |
|  в правке:                                           (OSM )  |
|  [name___] 12.3 km (Hiking v)(<-)(->)(share)(Done)  (Hm)(Rel)|
|                                                      (more)  |
|                                                      (SV  )  |
|                                                      ( +  )  |
|                                                      ( -  )  |
|                                                      (loc )  |
| 500 m                                                        |
| (c) OSM                    (profile)                         |
+--------------------------------------------------------------+
   (profile) -- только при активном маршруте
```

- **Слева сверху — маршрут** **[владелец]**: поиск, список треков `(=)`, новый маршрут `(+)` круглой кнопкой-иконкой, линейка рядом с `(+)`. Пока линия правится, на месте зоны — строка редактора, как сейчас. Число треков у `(=)` — решение change 1 (это данные, а не подпись) **[агент]**.
- **Справа — слои и навигация** **[владелец]**: 3–4 круглых превью подложек столбцом, под ними переключатели оверлеев (heatmap Strava, рельеф…), затем кнопка «ещё» — полный список; Street View — круглой кнопкой там же. Ниже — капсулы навигации, как в референсе: зум `+`/`−` одной капсулой без номера зума, геолокация. Сначала владелец предложил навигацию внизу по центру, после референса выбрал правую сторону: низ карты остаётся профилю.
- **Снизу — кнопка профиля высот**.
- **Кнопка профиля — только при активном маршруте** **[владелец]**. Активный — редактируемый трек, иначе трек с открытой панелью профиля **[владелец]**: после `Done` панель и кнопка остаются, пока панель не закрыта крестиком; профиль трека без правки — из меню трека. Уходит только правило «иначе первый видимый» (сценарий «Открыть профиль кнопкой» спеки `tracks` меняется).
- **Строка редактора**: имя правится в ней, рядом длина; иконка «поделиться» рядом с `Done` — меню с пунктами меню трека `Copy link for track`, `Save as GPX`, `Save as GPX with elevation`, `Save as KML` для этого трека **[владелец]** (тексты — как в `TrackList.tsx`: по ним ищут тесты). Меню трека в списке остаётся.
- **Поиск открывает ссылки на треки** **[владелец]**: всё, что понимает поле `Track URL`, вставляется в поиск, плейсхолдер подсказывает это; поле `Track URL` уходит. Файл — перетаскиванием на карту или иконкой в списке.
- **Вид** **[владелец]**: всё круглое и полупрозрачное, ближе к Liquid Glass; иконки без подписей, название — подсказкой при наведении и в `aria-label` (по нему ищут тесты). Цифры маршрута — данные, а не подпись: длина в строке редактора, подъём — только когда профиль трека уже посчитан (как сейчас у кнопки профиля, [polish-web-ui](../changes/archive/2026-10-10-polish-web-ui/design.md#макет-4a-владелец): запрос высот ради подписи тратит лимит API высот).
- **Место — главное** **[владелец]**: «мы должны максимально экономить место».

### Что это меняет в прежних решениях

- Подписанные кнопки вместо иконок (решение владельца по макету 4a, [polish-web-ui](../changes/archive/2026-10-10-polish-web-ui/design.md#макет-4a-владелец)) — отменено: иконки с подсказками.
- Кнопки карты как контролы MapLibre столбцом справа ([«Что Claude Design менять нельзя»](../changes/archive/2026-10-10-polish-web-ui/design.md#что-claude-design-менять-нельзя)) — остаются: зум и `GeolocateControl` справа, меняется вид (капсулы, без номера зума). Слежение и тост неактивной геолокации (`MapButtons.tsx`) не трогаются.
- Номер зума (спека `web-client`, «Масштаб и зум на карте») — убирается, линейка масштаба остаётся.
- «Телефон — полноценная цель» — так записано в design `polish-web-ui` со ссылками на ресёрч `new-ui.md` и архивы `record-*`, но в архивах `record-ui-decisions` и `record-new-ui-decisions` про телефон нет ни слова. Теперь телефон вторичен **[владелец]**.
- Change 1 правит строку «Раскладка интерфейса — макет Claude Design 4a» реестра `docs/architecture/decisions.md`, абзац «Раскладка» раздела «Приложение» в `AGENTS.md` и подвох про `top-12!` в `BaseMap.tsx`, если сдвинутся контролы.

## Телефон

Отложен в конец backlog **[владелец]**. Ветка `polish-phone-4a` (propose телефона под 4a, без кода и PR) удалена 2026-10-10: она верстала телефон под раскладку, которую заменяют три зоны. Факты с её кадров 2026-10-10 (`phone/portrait`, `phone/landscape`, `phone/390x844`), которые пригодятся, когда дойдёт черёд:

- Портрет Pixel 7 (412×839): профиль `min(12rem, 35dvh)` и панорама стопкой вместе со строкой кнопок — ≈ 62 % высоты окна, карты около трети, строка кнопок закрывает метку панорамы (`14-street-view-with-profile`).
- Альбом Pixel 7 (863×360 в Playwright): от 640 px ширины включается раскладка компьютера (`sm:`); с профилем и панорамой кнопки налезают на верхнюю строку, зум и геолокация уходят под панораму. Правило `max-height: 480px` не спасает.
- Редактор: названию остаётся одна буква (`09-route-editor-drawing`).
- Тост ошибки прокладки закрывает атрибуцию и линейку масштаба (`27-routing-error-toast-over-edit-panel`); поиск на 390×844 обрезан до `Search places, coo…`.
