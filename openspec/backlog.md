## Глобальное направление: полная автономия

Цель — свой продукт на базе nakarte, который не зависит от инфраструктуры автора `*.nakarte.me`. Решение владельца 2026-10-08: в апстрим не мерджимся и PR автору не открываем, код автора — справочник; правило «дифф с апстримом держим маленьким» снято (`AGENTS.md`, раздел «Апстрим»). Каждую задачу разбивать на changes через `/opsx:explore`.

- Переписать и обновить UI: сейчас это апстримный Leaflet + knockout. Начать с исследования: что оставить, на что переходить, как переносить поведение из `openspec/specs/` (они и есть контракт для новой версии).
- Свой бэкенд вместо авторских сервисов: ресёрч, решения и план changes — в `openspec/research/own-backends.md`. Зависимости из `src/config.js`:
  - `elevation.nakarte.me` и `tiles.nakarte.me/elevation` — высоты;
  - `tracks.nakarte.me` — хранилище треков для ссылок;
  - `nakarte.me/westraPasses`, `nakarte.me/geocachingSu` — данные перевалов и геокешинга: слои удалены из кода (`drop-author-scan-layers`), свои данные — пункт в «Новых возможностях»;
  - `tiles.nakarte.me/wikimedia_commons_images`, `mapillary.nakarte.me`, `proxy.nakarte.me/mapy/` — покрытие панорам: провайдеры Wikimedia Commons, Mapillary и mapy.cz удалены из кода (`remove-panorama-providers`), в панорамах только Google Street View;
  - `proxy.nakarte.me` заменён своим Worker `nakarte-cors-proxy`;
  - всё закрыто `drop-author-services` (2026-10-08): свои сервисы по умолчанию во всех сборках, подпись — ссылка на форк, деплой проверяет бандл на `*.nakarte.me`.
- Аудит системного дизайна: после всех бэкенд-сервисов (changes 1–7 из `own-backends.md`) и до переписывания UI. Пересмотреть систему целиком, а не по сервису: границы сервисов, контракты (сейчас они повторяют клиент автора, при новом клиенте их можно менять), хранилища и форматы данных, шаблон сервиса (тесты, CI, деплой), CORS и защиту от злоупотреблений, наблюдаемость, стоимость и переносимость с Cloudflare. Результат — документ в `openspec/research/` с решениями и списком переделок, он же вход для исследования UI.
- Security-аудит клона: возможные атаки и защита от них, в первую очередь то, что бьёт по деньгам на Workers Paid и R2. `Origin` подделывается любым `curl`, поэтому CORS от злоупотреблений не защищает. Проверить: флуд запросов к Worker (запросы и CPU-мс сверх квоты Paid) и к Pages Functions; чтения R2 (Class B) через сервис высот и тайлы; спам записей и рост хранилища в `nakarte-tracks`; `nakarte-cors-proxy` как открытый прокси (трафик, жалобы на IP Cloudflare); права и утечка `CLOUDFLARE_API_TOKEN`, ручные workflow с записью в R2; зависимости npm и cargo. Варианты защиты: Rate Limiting binding или WAF-правила, лимиты на ключ или IP, оповещения о расходах в Cloudflare, сужение прав токена. Результат — документ в `openspec/research/` и changes на найденное.
- Высоты точнее 3″: Copernicus GLO-30 (1″, DSM) вместо viewfinderpanoramas. Источник без учётки — OpenTopography (DGED 2023_1, анонимный S3 `opentopography.s3.sdsc.edu/raster/COP30/COP30_hh/`, 26 475 тайлов, 777 ГБ, сетка 3601×3601 с перекрытием); 2024_1 — только Copernicus Data Space с учёткой. Нужна атрибуция Copernicus; формат и ядро `workers/elevation` к размеру сетки не привязаны.

## Отложено

- Режим `'browser'`: при сбое запуска движка показывается неверное «BRouter is not running, start it with yarn local». Undo/redo и сохранение разметки проверены на проде 2026-10-07.
- Разрыв со спиннером: не проверены откат на прямую при ошибке и перетаскивание точки с двумя ожидающими отрезками.
- Слои Strava heatmap ждут секрет прокси `STRAVA_COOKIES` (куки CloudFront аккаунта Strava, заводит владелец скриптом `scripts/strava-heatmap-secret.mjs`, шаги — `AGENTS.md`). Проверено 2026-10-08 в Chrome владельца: вошедшая сессия получает тайл `200` с самой strava.com; странице куки не видны; с другого сайта (`img`, `fetch` с `credentials`) браузер их не шлёт, так что вариант «тайлы прямо из браузера пользователя» не работает. Куки живут около суток (выданные 2026-10-08 истекали 2026-10-09 06:18 UTC), вручную это ежедневная работа: автоматизировать обновление — приоритет выше остальных пунктов про Strava, например Worker по расписанию получает их по сессии Strava из секрета, — сначала выяснить, какой запрос страницы heatmap их выдаёт. Проверить условия Strava на показ heatmap в стороннем приложении.
- Импорт Strava не работает для новых активностей ни в клоне, ни у автора: `activities/<id>/streams` без входа — `301` на `/login`, `401` или `403`; у `proxy.nakarte.me` проходят только закешированные. Импорт Garmin Connect не работает через свой прокси: Cloudflare bot management Garmin отвечает `403` на curl, node fetch и Worker, у автора проходит только с его сервера. Сетевые тесты обоих убраны из CI (2026-10-08). Варианты: импорт через OAuth API Strava и Garmin, импорт из файла как основной путь, убрать из UI.
- Импорт Wikiloc не работает ни в клоне, ни у автора: с 2026-10-07 wikiloc отдаёт Cloudflare JS-челлендж (`403`) на любой запрос не из браузера, через любой прокси и с любым `User-Agent`. Сетевые тесты wikiloc убраны из CI. Варианты: убрать импорт из UI или ждать, пока wikiloc откроет доступ.
- Лицензия CheerpJ Community: в `AGENTS.md` записано, что нужно указать авторство, в UI его нет; условия по первоисточнику не сверены.
- Закрепить digest образа `brouter:nightly` в деплое, чтобы профили и `lookups.dat` движка не менялись незаметно (см. риски в `changes/add-pages-autodeploy/design.md`).
- Проверка в Firefox, Safari и на телефоне.
- Свой ключ Google для Street View, если понадобится чистая панорама. Сейчас клон, как nakarte.me, грузит Maps JavaScript API без ключа (`keyless-street-view`) и прячет режим разработки Google своим CSS (`hide-street-view-dev-overlay`); это против условий Google, и Google может режим закрыть или сменить вёрстку. Ключ — секрет GitHub `GOOGLE_MAPS_API_KEY`, деплой подставит его сам. Шаги владельца: проект в Google Cloud с биллингом (карта нужна даже для бесплатного объёма), включить Maps JavaScript API, создать ключ с ограничениями Websites `https://nakarte-routing.pages.dev` и API только Maps JavaScript API ([рекомендации Google](https://developers.google.com/maps/api-security-best-practices)), бюджет с оповещением, `gh secret set GOOGLE_MAPS_API_KEY`. Цена по [прайсу Google Maps Platform](https://developers.google.com/maps/billing-and-pricing/pricing): Dynamic Street View — 5 000 бесплатных панорам в месяц, дальше $14 за 1 000; покрытие — тайлы без ключа, не тарифицируются.
- Спайк BeeRouter → `wasmJs`: собрать, прогнать 6 эталонов из `experiments/wasm/routes.json`, сравнить с CheerpJ по скорости, размеру и памяти.

## Данные из ответа BRouter

В `features[0].properties` есть `track-length`, `filtered ascend`, `total-time` и `messages` — таблица по участкам, где колонка `WayTags` содержит `highway=…`, `surface=…`. Параметры запроса: `nogos`, `polylines`, `polygons`, `alternativeidx`, `straight`, `roundTrip*`, `profile:<переменная>`. Через `profile:` переопределяется любая `assign`-переменная профиля, даже без пометки `%…%`.

- Время в пути и набор высоты (`total-time`, `filtered ascend`) в подсказке трека.
- Раскраска трека по покрытию и типу дороги из `messages.WayTags`.
- Зоны, которые маршрут обходит (`nogos`).
- Кольцевой маршрут заданной длины (`roundTripDistance`).
- Альтернативы маршрута (`alternativeidx` 0–3).

## Новые возможности

Начать с ресёрча: что именно рисует MapMagic (свой стиль на данных OSM или сторонний слой), какие готовые туристические стили на OSM можно взять (условия, ключ, квоты, цена) и сравнить с тем, что уже есть в `src/layers.js` (OpenTopoMap, CyclOSM, Thunderforest Outdoors), или свой стиль на векторных тайлах с раздачей с Cloudflare. Там общий список вещей и списки под конкретные походы, у вещи вес (и цена), категории с круговой диаграммой, разделение на базовый вес, надетое и расходники, импорт и экспорт CSV, публичная ссылка. Здесь — список, привязанный к треку, рядом с длиной и набором высоты. Код LighterPack под GPL-2.0 ([galenmaly/lighterpack](https://github.com/galenmaly/lighterpack)), в MIT-форк его не переносить, только идею.

Начать с ресёрча (`openspec/research/`): можно ли вообще — есть ли у Яндекса публичный API панорам (JS API Карт, модуль панорам) и тайлы покрытия, условия использования (бесплатный тариф, разрешены ли некоммерческие и открытые проекты, обязательные ключ и атрибуция, запреты на кеширование и проксирование), покрытие за пределами России (Грузия, Кавказ, Казахстан); как дорого — тарифы, лимиты бесплатного объёма, что будет при превышении. ## Варианты движка в браузере

Выбран CheerpJ (замеры 2026-10-06). Остальное — на случай, если упрёмся в его слабые места. Цена — грубая оценка, риск — то, что может убить вариант.

| Вариант | Суть | Что известно | Цена | Главный риск |
|---|---|---|---|---|
| CheerpJ | JVM в Wasm, гоняет jar BRouter как есть | работает, замерено | интеграция: дни | память, холодный старт, чужой CDN и лицензия |
| BeeRouter → `wasmJs` | форк BRouter на Kotlin Multiplatform (MPL-2.0), те же `.brf`, `.rd5`, `lookups.dat`; добавить таргет Kotlin/Wasm | сейчас собирается только `jvm` и `linuxX64`, зависимости публикуют `js` и `wasmJs`; чтение данных идёт через синхронный `RandomAccessReader` | спайк: 1–3 дня | под wasm никто не собирал; молодой проект, 0.0.6 |
| TeaVM | AOT-компиляция Java BRouter в Wasm GC или JS | аудит по коду: 2 класса правок, синхронное чтение тайлов внутри A* | PoC 1–2 дня, рабочая версия 5–9 | скорость A* не мерена, подмена ФС через внутренний API |
| Kotlin-порт из `stefanhoelzl/tracks` | ядро BRouter 1.7.10 переведено J2K, паритет с brouter.de побайтно (MIT) | прецедент и тест-методика; таргеты jvm, linuxX64, iOS | как у BeeRouter | нашли тихие расхождения `(int) x` и `float += double` |
| Другие компиляторы Java → Wasm | GraalVM Web Image, J2CL/J2Wasm, Bytecoder, JWebAssembly | GraalVM экспериментальный: ФС только в памяти, потоков нет; J2CL без `File` и `RandomAccessFile`; остальные заморожены | — | не годятся без переделки I/O |
| Переписать ядро на Rust | свой движок, совместимый с `.rd5` и `.brf`, через `wasm-bindgen` | готового порта нет ни на одном языке; A* и обвязка есть в крейтах; дорогие части — язык `.brf` и кодек `.rd5` | недели: ~18 тыс. строк Java в core, mapaccess, expressions, codec, util | паритет с BRouter (float, округления), объём |
