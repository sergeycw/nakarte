## Внешние зависимости и риски

Сервисы автора `*.nakarte.me` отключены (`drop-author-services`), но клон зависит от чужих сервисов, которые могут сломаться без нашего участия. Список — чтобы при поломке сразу знать, что отвалилось и что уже есть на этот случай. Сверено по коду 2026-10-08. Пункты с отдельной записью ниже здесь только названы.

- CheerpJ (`cjrtnc.leaningtech.com/4.3/loader.js` в `lib/brouter/browser-engine.js`): рантайм движка в браузере грузится с CDN Leaning Technologies. Упадёт CDN или сменится версия — в клоне не работает прокладка маршрута (серверный режим не затронут). Защиты нет; держать рантайм у себя лицензия Community не позволяет (пункт в «Отложено»). Скрипт грузится без SRI: подмена на CDN — чужой JS на origin клона; SRI на `loader.js` возможен, только если файл под `/4.3/` неизменен (не подтверждено, security-аудит, п. 6).
- brouter.de: источник тайлов роутинга (`*.rd5`) и `lookups.dat` для синхронизации по понедельникам. Тайлы лежат в нашем R2, поэтому недоступность brouter.de только останавливает обновление; смена `lookups.dat` роняет синхронизацию. Синхронизация сверяет `lookups.dat` только с brouter.de, а профили и `lookups.dat` движка берутся из образа `brouter:nightly`; 2026-10-08 файлы совпадают побайтно (пункт про digest образа — в «Отложено»).
- Strava heatmap: держится на сессии `STRAVA_SESSION`, срок которой неизвестен; без неё — анонимные тайлы до z12, письмо от `strava heatmap check`. Подробности — пункт в «Отложено».
- Google Street View без ключа: против условий Google, режим разработки может закрыться. Пункт про свой ключ — в «Отложено».
- Импорт треков по ссылкам Strava, Garmin Connect и Wikiloc не работает: сервисы режут запросы не из браузера. Пункты — в «Отложено».
- Поиск: photon.komoot.io (публичный инстанс Komoot, без ключа и без гарантий) и mapy.cz через свой прокси. Ляжет photon — не работает поиск по названиям, поиск по координатам и ссылкам — работает.
- Тайловые слои: OSM, OpenTopoMap, CyclOSM, Waymarked Trails, Thunderforest (без ключа; 2026-10-08 тайл приходит без водяного знака), Яндекс, Bing, Google, ESRI, национальные (swisstopo, Kartverket, Lantmäteriet, IGN и др.), слои через прокси (Wikimapia, Strava). Ломаются по одному, слой просто пустеет; так же было у автора. Массовой проверки слоёв нет — кандидат: workflow, который раз в неделю запрашивает по тайлу каждого слоя.

## Отложено

- Разрыв со спиннером: не проверены откат на прямую при ошибке и перетаскивание точки с двумя ожидающими отрезками.
- Strava heatmap: z13–z16 живут, пока жива сессия `STRAVA_SESSION`, а её срок неизвестен: в браузере `_strava4_session` без `Expires`, куки «запомнить меня» нет (`--probe` в `scripts/strava-session-secret.mjs`), и ни одна страница сессию не продлевает: `/dashboard`, `/api/next/session/get`, счётчик уведомлений и heatmap отвечают без `Set-Cookie: _strava4_session` (`--rotation`, 2026-10-08). Срок решает сервер Strava; если он продлевается активностью, его держат ежедневные заходы прокси, срок покажет `strava heatmap check`. Новую сессию даёт только вход человека: вход защищён reCAPTCHA v3 Enterprise на `/login/request_otp` и `/session`, автологин по крону не делаем; удалённый браузер получил бы ту же сессию. Если сессия окажется короткой — расширение Chrome, которое после ручного входа само отправляет новую `_strava4_session` в прокси (KV), чтобы обойтись без скрипта. Кеш тайлов heatmap в R2 по требованию (только открытые тайлы, TTL около месяца) снизит нагрузку на Strava и задержку; выкачивать всю heatmap нецелесообразно (оценка 2026-10-08: 0.6–0.8 млрд тайлов на 4 слоя до z16, 3–7 ТБ, ~$3 000 за записи в R2 на прогон, месяцы на одном аккаунте). Проверить условия Strava на показ heatmap в стороннем приложении и на автоматический сбор.
- Импорт Strava не работает для новых активностей ни в клоне, ни у автора (решение владельца 2026-10-08: в новом UI импорта Strava, Garmin Connect и Wikiloc нет — `record-new-ui-decisions`; пункт уйдёт вместе со старым клиентом): `activities/<id>/streams` без входа — `301` на `/login`, `401` или `403`; у `proxy.nakarte.me` проходят только закешированные. Импорт Garmin Connect не работает через свой прокси: Cloudflare bot management Garmin отвечает `403` на curl, node fetch и Worker, у автора проходит только с его сервера. Варианты: импорт через OAuth API Strava и Garmin, импорт из файла как основной путь, убрать из UI.
- Импорт Wikiloc не работает ни в клоне, ни у автора (в новом UI его нет, см. пункт выше): с 2026-10-07 wikiloc отдаёт Cloudflare JS-челлендж (`403`) на любой запрос не из браузера: на всех хостах (`www`, `ru`, без поддомена, embed, даже `robots.txt`), напрямую и через любой прокси, с любым `User-Agent`. Варианты: убрать импорт из UI или ждать, пока wikiloc откроет доступ.
- Лицензия CheerpJ Community: держать рантайм у себя нельзя — «Self-Hosting not allowed» для Community, только по коммерческой лицензии ([licensing](https://cheerpj.com/licensing/), 2026-10-08), то есть требование «Рантайм с CDN Leaning Technologies» в `browser-routing-engine` верно. Не сверено, нужно ли указывать авторство в UI (сейчас его нет).
- Закрепить digest образа `brouter:nightly` в деплое, чтобы профили и `lookups.dat` движка не менялись незаметно (см. риски в `changes/archive/2026-10-07-add-pages-autodeploy/design.md`).
- Проверка в Firefox, Safari и на телефоне.
- Свой ключ Google для Street View, если понадобится чистая панорама. Сейчас клон, как nakarte.me, грузит Maps JavaScript API без ключа (`keyless-street-view`) и прячет режим разработки Google своим CSS (`hide-street-view-dev-overlay`); это против условий Google, и Google может режим закрыть или сменить вёрстку. Ключ — секрет GitHub `GOOGLE_MAPS_API_KEY`, деплой подставит его сам. Шаги владельца: проект в Google Cloud с биллингом (карта нужна даже для бесплатного объёма), включить Maps JavaScript API, создать ключ с ограничениями Websites `https://nakarte-routing.pages.dev` и API только Maps JavaScript API ([рекомендации Google](https://developers.google.com/maps/api-security-best-practices)), бюджет с оповещением, `gh secret set GOOGLE_MAPS_API_KEY`. Цена по [прайсу Google Maps Platform](https://developers.google.com/maps/billing-and-pricing/pricing): Dynamic Street View — 5 000 бесплатных панорам в месяц, дальше $14 за 1 000; покрытие — тайлы без ключа, не тарифицируются.
- Серверный BRouter на Oracle Cloud Always Free (решение владельца 2026-10-08: попробовать отдельно, позже). Ресурсы бесплатно навсегда: ARM 2 OCPU, 12 ГБ, 200 ГБ дисков, 10 ТБ исходящего в месяц ([Always Free](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)); мир `*.rd5` ≈ 10 ГБ. Выигрыш против CheerpJ — скорость в 3–4 раза, нет холодного старта и 0.6–0.8 ГБ на вкладку, нет зависимости от CDN CheerpJ. Риски: Oracle забирает простаивающие инстансы (за 7 дней p95 CPU, сеть и память ниже 20%) — малый трафик под это попадает; «out of host capacity» при создании; сервер один, значит CheerpJ остаётся запасным движком. Работа: BRouter в Docker, HTTPS, лимит частоты, еженедельное обновление тайлов. Цены платных VPS и требования BRouter — `openspec/research/new-ui.md`, «Движок прокладки».
- Спайк BeeRouter → `wasmJs`: собрать, прогнать 6 эталонов из `experiments/wasm/routes.json`, сравнить с CheerpJ по скорости, размеру и памяти.

## Редактор и активности

- Настройки активности в UI: уровень SAC (`SAC_scale_limit`), `consider_elevation`, `allow_steps`.
- Перестраивать маршрут во время перетаскивания, с ограничением частоты запросов.
- Импортированная линия в редакторе нового приложения: каждая точка — опорная, на десятках тысяч точек перетаскивание тормозит (замер — архив `add-web-route-editor`, «Перетаскивание внутри большой редактируемой линии»). Варианты: показывать опорные точки только на крупном масштабе или упрощать линию при входе в редактирование.

## Данные из ответа BRouter

В `features[0].properties` есть `track-length`, `filtered ascend`, `total-time` и `messages` — таблица по участкам, где колонка `WayTags` содержит `highway=…`, `surface=…`. Параметры запроса: `nogos`, `polylines`, `polygons`, `alternativeidx`, `straight`, `roundTrip*`, `profile:<переменная>`. Через `profile:` переопределяется любая `assign`-переменная профиля, даже без пометки `%…%`.

- Время в пути и набор высоты (`total-time`, `filtered ascend`) в подсказке трека.
- Раскраска трека по покрытию и типу дороги из `messages.WayTags`.
- Зоны, которые маршрут обходит (`nogos`).
- Кольцевой маршрут заданной длины (`roundTripDistance`).
- Альтернативы маршрута (`alternativeidx` 0–3).

## Новые возможности

- Слой OpenStreetMap по умолчанию — в туристическом стиле, как базовая карта [MapMagic](https://mapmagic.app) (запрос владельца 2026-10-08, скриншот района Тбилиси): отмывка рельефа, лес и растительность цветом, тропы и туристические маршруты выделены, подписи вершин и перевалов. Сейчас по умолчанию стоит обычный `tile.openstreetmap.org`. Ресёрч — `openspec/research/new-ui.md`, раздел «Карта» (на чём сделан MapMagic, источники векторных тайлов и рельефа, цены); делается change `add-outdoor-basemap` из его списка.
- Погода на маршруте (идея владельца 2026-10-08): при планировании велосипедного маршрута — направление и сила ветра вдоль трека (где встречный, где попутный), а если у маршрута указаны даты — прогноз погоды по пути. Начать с ресёрча (`openspec/research/`): источники прогноза и ветра с CORS и без ключа или с бесплатным тарифом (например, Open-Meteo, MET Norway), горизонт и шаг прогноза, условия использования и атрибуция, квоты и нужен ли свой прокси или кеш на Worker'е; как показывать (стрелки ветра вдоль трека, цвет отрезков, панель по дням) и где хранить даты маршрута (в ссылке, в автосохранении). Зависит от редактора маршрута и автосохранения нового UI (changes `add-web-route-editor`, `add-web-autosave`).
- Приоритет низкий. Встроенный аналог [LighterPack](https://lighterpack.com): списки снаряжения для похода. Там общий список вещей и списки под конкретные походы, у вещи вес (и цена), категории с круговой диаграммой, разделение на базовый вес, надетое и расходники, импорт и экспорт CSV, публичная ссылка. Здесь — список, привязанный к треку, рядом с длиной и набором высоты. Код LighterPack под GPL-2.0 ([galenmaly/lighterpack](https://github.com/galenmaly/lighterpack)), в MIT-форк его не переносить, только идею.
- Спутниковый слой с выбором даты, как в [EOSDA LandViewer](https://eos.com/landviewer/): посмотреть свежие снимки района, например, лежит ли ещё снег на перевале. Начать с глубокого ресёрча (`openspec/research/`), можно ли это сделать вообще и как: источники снимков с датами (Sentinel-2, Landsat и т. п.), разрешение и частота съёмки, облачность и её фильтр, лицензии и условия показа, бесплатные API и квоты (например, Copernicus Data Space, Sentinel Hub, AWS Open Data), тайлинг снимков на лету или готовые WMTS, стоимость на Cloudflare и защита от злоупотреблений. Результат — вывод «делать или нет» и план changes.

Начать с ресёрча (`openspec/research/`): можно ли вообще — есть ли у Яндекса публичный API панорам (JS API Карт, модуль панорам) и тайлы покрытия, условия использования (бесплатный тариф, разрешены ли некоммерческие и открытые проекты, обязательные ключ и атрибуция, запреты на кеширование и проксирование), покрытие за пределами России (Грузия, Кавказ, Казахстан); как дорого — тарифы, лимиты бесплатного объёма, что будет при превышении.   - Как собирает автор — открытый код [wladich/westra_passes_for_nakarte](https://github.com/wladich/westra_passes_for_nakarte) (без файла лицензии): JSON API `https://westra.ru/passes/classificator.php?place=<id>&export=json&key=<API_KEY>`, корень `place=0` и по запросу на каждый из ~25 районов верхнего уровня. Без ключа отдаётся HTML. Как получить ключ, публично не описано — спрашивать webmaster@westra.ru. Покрытие автор считает на numpy, scipy и shapely (`passes_coverage.py`), подписи регионов — свои GPX в `data/westra/`, не с сайта.
  - Вестра без ключа: `classificator.php?place=<id>&type=new&export=kml|xls|wpt` по району (KML Урала 0.8 МБ, дерево районов папками). Нет автора перевала, авторов комментариев и id регионов (их брать из HTML классификатора); отчёты в KML — текстом. Автор есть только на страницах `/passes/Passes/<id>` (17 тыс. страниц). `robots.txt` эти пути не запрещает; страницы условий использования нет, только «© Турклуб «Вестра»» и в KML «Открытый проект турклуба «Вестра»».
  - geocaching.su: старый скрипт автора [geocaching_to_json](https://github.com/wladich/geocaching_to_json) брал `kml/kml_lite.php` (сейчас `500`). Работает `https://geocaching.su/kml/kml.php`: один запрос, 16.8 МБ gzip / 71.5 МБ, 31 685 тайников, ≈ 17 с; в названиях вырезаны кавычки, у части координаты 0,0, набор id расходится с файлом автора на сотни. `robots.txt` запрещает `/api/` и `/ajax/`, `/kml/` — нет. [Соглашение «Авторское право»](https://geocaching.su/?pn=114): копирование и воспроизведение материалов — только для личного некоммерческого использования, иное — с согласия автора или администрации и со ссылкой на сайт. Без согласия администрации не делать.
  - Схема реализации, если вернёмся: Worker `workers/scrapers` по шаблону `workers/tracks` с Cron Trigger раз в сутки → R2, проверка схемы против фикстур с файлов автора до записи, раздача с CORS `*` и `Cache-Control` ≥ 1 ч, лимиты по `worker-limits`.

## Сопровождение

- Тайлы `*.rd5` синхронизация перезаписывает под тем же ключом. Склейку старых кусков из кеша браузера с новыми закрыл `no-store` (`fix-tile-cache-after-sync`), но страница, открытая во время синхронизации, держит в движке индекс старой версии тайла и дочитывает данные новой. Архив тайлов высот так же перезаливается одним объектом, и после него нужен ручной передеплой Worker'а. Закрывает версия в ключе и манифест с текущим снимком (аудит системного дизайна, «Хранилища и форматы данных»).
- Наблюдаемость: ошибок клиента не видно (`sentryDSN` и `eventsLogUrl` пустые), а маршрут в клоне считает браузер: отказ CDN CheerpJ или исключение Java видит только пользователь. Варианты: Sentry (DSN уже поддержан кодом) или свой `POST /events` в существующий Worker с записью в Workers Logs; события без координат. Расписания GitHub отключает после 60 дней без коммитов — это касается синхронизации тайлов, `strava heatmap check` и `prod check`.
- Мелочи хранилищ: у объектов `nakarte-tracks` есть время записи (`customMetadata.created`, с `limit-track-writes`), но нет версии `nktk`.
- Безопасность после security-аудита (цены и формулы — `openspec/research/security-audit.md`, «Итог»):
  - P2. Выключатель расходов: потолка у Cloudflare нет, бюджетные оповещения — письмо раз в сутки. Workflow по расписанию читает GraphQL Analytics и выше порога выключает `workers.dev` у Worker'ов; нужен токен Analytics Read + Workers Scripts Edit — решение владельца.
  - P2. Тайлы высот z10–11 считаются на лету без бюджета чтений R2: до $63–103 в месяц с одного IP при лимите 600 в минуту. Тратить тот же бюджет чтений, что API высот.
  - P2, отложено владельцем 2026-10-08. Секреты деплоя в environment `production` с веткой `master`: сначала владелец заводит environment и переносит секреты, потом `environment: production` в job'ы с секретами.
  - P2, отложено владельцем 2026-10-08. Сессия Strava в прокси — личный аккаунт владельца: утечка секрета или выкачка heatmap через прокси бьют по нему. Выпустить `STRAVA_SESSION` от отдельного аккаунта.
  - P3. `cargo audit` и `npm audit --omit=dev` шагом в `check-<сервис>.yml`; разовая проверка 2026-10-08 — чисто.
  - P3. Workers Logs под флудом добавляют $0.60 за миллион событий: понизить `head_sampling_rate` у прокси, если трафик вырастет (логи кук Strava при этом станут выборочными).
- Тесты karma для `lib/brouter` и для отмены устаревших ответов в обоих направлениях рисования.

## Варианты движка в браузере

Выбран CheerpJ. Замеры CheerpJ 4.3 (2026-10-06): 10 км — 0.3–0.55 с на прогретом движке, сервер в 3–4 раза быстрее; холодный старт ≈ 5–6 с; 0.6–0.8 ГБ RSS на вкладку. В Web Worker (2026-10-08, change `spike-engine-in-worker`) главный поток свободен, движок — ≈ 0.3–0.5 ГБ `phys_footprint`; RSS на macOS эту цифру занижает, а старые 0.6–0.8 ГБ — оценка по RSS другого стенда. Остальное — на случай, если упрёмся в его слабые места. Цена — грубая оценка, риск — то, что может убить вариант.

| Вариант | Суть | Что известно | Цена | Главный риск |
|---|---|---|---|---|
| CheerpJ | JVM в Wasm, гоняет jar BRouter как есть | работает, замерено | интеграция: дни | память, холодный старт, чужой CDN и лицензия |
| BeeRouter → `wasmJs` | форк BRouter на Kotlin Multiplatform (MPL-2.0), те же `.brf`, `.rd5`, `lookups.dat`; добавить таргет Kotlin/Wasm | сейчас собирается только `jvm` и `linuxX64`, зависимости публикуют `js` и `wasmJs`; чтение данных идёт через синхронный `RandomAccessReader` | спайк: 1–3 дня | под wasm никто не собирал; молодой проект, 0.0.6 |
| TeaVM | AOT-компиляция Java BRouter в Wasm GC или JS | аудит по коду: 2 класса правок, синхронное чтение тайлов внутри A* | PoC 1–2 дня, рабочая версия 5–9 | скорость A* не мерена, подмена ФС через внутренний API |
| Kotlin-порт из `stefanhoelzl/tracks` | ядро BRouter 1.7.10 переведено J2K, паритет с brouter.de побайтно (MIT) | прецедент и тест-методика; таргеты jvm, linuxX64, iOS | как у BeeRouter | нашли тихие расхождения `(int) x` и `float += double` |
| Другие компиляторы Java → Wasm | GraalVM Web Image, J2CL/J2Wasm, Bytecoder, JWebAssembly | GraalVM экспериментальный: ФС только в памяти, потоков нет; J2CL без `File` и `RandomAccessFile`; остальные заморожены | — | не годятся без переделки I/O |
| Переписать ядро на Rust | свой движок, совместимый с `.rd5` и `.brf`, через `wasm-bindgen` | готового порта нет ни на одном языке; A* и обвязка есть в крейтах; дорогие части — язык `.brf` и кодек `.rd5` | недели: ~18 тыс. строк Java в core, mapaccess, expressions, codec, util | паритет с BRouter (float, округления), объём |
| Переписать ядро на TS | то же, но на JS | как у Rust; `float` эмулируется через `Math.fround` | как у Rust | скорость A* в JS |
| Valhalla в Wasm | `tobilg/valhalla-wasm`: готовый движок, тайлы `.gph` по Range | работает, wasm 9.9 МБ, есть `bicycle` и `pedestrian` с `sac_scale` | своя сборка и раздача тайлов, переписать активности | другой движок и данные, высот в графе нет |
| Экзотика | граф из векторных тайлов OpenMapTiles или PMTiles, SQLite по HTTP Range, DuckDB-Wasm | готового роутинга нет; в OMT теряется топология и нет высот; DuckDB умеет только невзвешенный путь | исследование | всё |

Не существует: OSRM в Wasm, pgRouting в PGlite, современный GraphHopper в браузере.

Параллельный расчёт отрезков: у каждого Web Worker свой экземпляр CheerpJ (проверено в `spike-engine-in-worker`), поэтому несколько воркеров считали бы отрезки одновременно. Цена — ≈ 0.3–0.5 ГБ и холодный старт на воркер; сейчас движок один на страницу, очередь из быстрых кликов проходит за секунды. Вернуться, если длинные маршруты из многих отрезков станут ждать заметно.
